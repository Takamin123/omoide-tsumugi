# 出し比べ用の架空の家族

プロンプトの出し比べ（`.claude/agents/qa-engineer.md` の仕事 2）で使う、架空の家族のデータ。入り口づくり（Sonnet）と文字起こしの整形（Haiku）に同じものを使う。

- 人物・家族・出来事はすべて作りもの。実在の人や家族のことは書かない。地名は「広島」「東京」くらいの広さに留める
- 写真と録音のファイルは置かない。写真は「説明」（`photo_guesses.description` に入るような文）だけを持つ
- 形は `types.ts` の `FamilyFixture`。欄の名前は `src/server/db/schema.ts` に合わせてある。ID は読みやすい固定の文字列

## family-a.json

広島の祖父母（ばあば、じいじ）、東京の母、広島の叔父、東京の孫（高校生）。祖父母と叔父は広島の言葉で話す。

| 語り | 話し手 | 見るためのもの |
|---|---|---|
| n01 | ばあば（声） | 方言（こまい、じゃけえ、ぶち）。時期は語りの中にしかない |
| n02 | じいじ（声） | 極端に短い。整形や引用で言葉を足さないか |
| n03 | ばあば（声） | 話がそれて戻る。それた先（嫁入りの着物）が別の写真につながる |
| n04 | じいじ（声） | 人・家・名前があいまい。推測で埋めないか。名前を思い出させる問いかけにしないか |
| n05 | ばあば（声） | 聞き間違いらしき所が三つ（`mishearings` に期待値）。整形が勝手に直さず、あやしい所として挙げるか |
| n06 | 母（文字） | n01 への返事。家族の言葉に「覚えてる」がある |
| n07 | 叔父（文字） | n06 への返事で、言うことが食い違う。どちらかに決めないか |
| n08 | 孫（文字） | 短い文字の語り |
| n09 | 母（声） | 標準語のふつうの語り。家族自身の推測（「たぶん」）を断定に変えないか |
| n10 | 孫（声） | 写真の説明の「年配の男性」を、家族がじいじだと語っている |

写真の罠:

- p01 は古い紙の写真を撮り直したもの。`takenAt` は撮り直した日（2026 年）で、写っている時期ではない
- p05 には語りがない
- 撮影日のない写真が多い（紙の写真の取り込みを想定）

## 期待値の欄

- `traits`: 語りの性質（方言、短い、それる、あいまい、聞き間違い、返事）
- `mishearings`: 聞き間違いのつもりの箇所。`heard` は `transcript` の中にちょうど一度だけ出てくる。`intended` が本来の言葉
- `note`: このデータの意図

`traits`、`mishearings`、`note` は期待値と説明。**プロンプトにもアプリにも渡さない。** 渡すと、答えを教えた出し比べになる。

## 足すとき

- 架空のことだけを書く。身近な人の話を少し変えて使うこともしない
- `mishearings` の `heard` が `transcript` にちょうど一度出てくること、`replyToId` の先が同じ写真の語りであることを保つ
