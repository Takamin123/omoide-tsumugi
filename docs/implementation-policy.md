# 実装の方針（迷ったときの倒し方）

細かい規約ではなく、迷ったときにどちらに倒すかだけを書く。どう実装したかはソースを正とする。理由は [0007](decisions/0007-implementation-policy.md)。

## 1. 作品ならではのもの

### ログ
- 出してよい: ID（家族、人、写真、語り、入り口、処理）、件数、所要時間、HTTP のステータス、モデル名、プロンプトの版、トークン数、エラーの種類、環境名
- 出さない: 家族の名前、語り・文字起こし・問いかけの本文、写真や録音の URL（署名付きを含む）、合言葉・cookie・Authorization、緯度経度、連絡先
- **迷ったら出さない。** 本文が要るなら ID を出し、データベースで引く
- 一回の処理（リクエスト一つ、毎朝の処理の家族一人分）に処理の ID を付け、その処理のすべてのログに入れる。調査はこの ID で追う
- 外部ライブラリのエラーをそのまま出さない（入力値を含むことがある）。種類と ID に置き換える
- Claude に渡したプロンプトの全文は、本番とプレビューでは保存もログもしない。代わりに、プロンプトの版、モデル名、入力に使った語りの ID、トークン数を入り口と一緒に保存し、組み直せるようにする。全文を見てよいのは、手元の開発用のスイッチと、架空の家族での出し比べだけ

### 高齢の人の画面の最低ライン
- 文字: 語り・問いかけ・ボタンは 20px 以上。補助の文字も 16px 以上。行間 1.5 以上。rem で指定し、ブラウザの文字の大きさの設定を妨げない
- コントラスト比: 文字は 4.5:1 以上。ボタンの輪郭やアイコンは 3:1 以上。色だけで意味を伝えない
- 押せる場所: 48×48px 以上、隣との間は 8px 以上。その画面の主な動作は、横いっぱい・高さ 64px 以上
- 一画面に主な動作は一つ。横スクロールを作らない
  - 例外は一つだけ: アルバムで、語りのある写真を横に並べた帯（家族の画面と祖父母の画面。祖父母の画面は大きさだけ違う。0043）。帯の外（ページ全体、語りの欄）は横に動かさない。帯のすべての写真に、横の操作なしで届く（一枚ずつ動かすボタンと、語りの縦スクロール）。いま何枚目かを文字で出す
- 確かめ方: 幅 375px と 360px（らくらくスマホなどの高齢者向けの機種）で文字を 150% にしても崩れない。数値はスタイルの定数に置く。数値は上げてよいが、下げない

### 操作に応える手触り
- 押した瞬間に応える: 押せるものは、押した瞬間に見た目が変わる（沈む・色が変わる）。結果を待つ間も、押されたことが分かる。二度押しで同じことが二度起きないようにする
- 指に付いてくる: めくる・ずらす操作は、指の動きにそのまま付いてくる。離したら、止まる位置まで自然に滑る
- 何が起きたかを動きで見せる: 開く・閉じる・送る・置くは、元の場所とのつながりが見える短い動き（0.2〜0.3 秒）で見せる。急に画面を切り替えない
- 待たせるときは進み具合を見せる: 送る・足す・読み込むが 1 秒を超えうるときは、何をしているかと進み具合を出す
- 動きは操作への応えだけ: 何もしていないときに動くもの（揺れる、自動でめくる、勝手に流れる）を作らない
- 動きを減らす設定（prefers-reduced-motion）では、動きを付けずにその場で切り替える
- 安い端末（らくらくスマホなど）でも滑らかに: 動かすのは位置・大きさ・透明度（transform と opacity）だけ。動きのために重い描き方をしない
- 確かめ方: 実機かそれに近い大きさで、押す・めくる・閉じるを実際に触って確かめる。テストの合否だけで済ませない
- 理由: 写真一枚一枚を丁寧に扱う場であることを、見た目だけでなく手触りでも伝える（人間、2026-11-03）

### 家族に見せる言葉
- です・ます、短い文。英語やカタカナの専門語を使わない。AI の存在を前に出さない（「AI が作りました」「分析しました」を出さない）
- アプリの固定の言葉（ボタン、案内、エラーの文）は、クライアントの一か所にまとめる。サーバーは日本語の文を返さず、エラーの種類だけを返す
- Claude が作る言葉（問いかけ）は固定の言葉ではなく**データ**。出所つきの「推測」として保存し、画面では問いかけの枠にだけ出す
- 「添える家族の言葉」は語りからの引用そのもの。Claude には語りの ID と範囲だけを返させ、本文はアプリがデータベースから引く。Claude に言い換えさせない

## 2. Claude の呼び出し

- すべて zod のスキーマで定義した構造化出力で受ける。自由文の欄は最小限にし、写真や語りは ID で受ける
- 受け取った後に、中身を機械的に検査する: 引用の ID が実在するか、問いかけは一つで 60 字以内か、「覚えていますか」のような試す言い回しがないか。方針をプロンプトに書くだけに頼らない
- 時間切れは 60 秒。再試行は 1 回（合計 2 回）、前に 2 秒待つ。429 は Retry-After に従い、最長 30 秒待つ
  - 再試行する: 時間切れ、429、5xx、接続エラー、スキーマや中身の検査の違反
  - 再試行しない: 429 以外の 4xx、認証エラー、入力が大きすぎる
- 壊れた応答の一部を拾って使わない。全か無か
- 渡す語りは新しいものから、合わせて 20,000 字まで。上限は定数にする
- 渡すのは要るものだけ。写真は縮小済み。合言葉、連絡先、緯度経度の生の値は渡さない
- 用途ごとのモデルは、一か所の対応表（用途名 → モデル名）で持つ。迷ったら、**家族に見える言葉を作る用途は Sonnet、見えない整理と整形は Haiku**。Opus を使うかは人間が決める（費用）
- プロンプトは用途ごと・版ごとに一つのファイルにする（`src/server/prompts/<用途>/v<N>.md`）。使った版の文字列を保存に入れ、一度使った版のファイルは書き換えない。変えたら出し比べを通し、判断を decisions に残す
- 家族が画面を開いている最中に Claude を呼ばない。入り口は毎朝の処理で作っておく。文字起こしと整形は、受け取ったことを先に返してから背景で行う

### 失敗したとき
- **入り口が作れなかった人には、Claude なしの「固定の入り口」を出す。** 写真はルールで選ぶ。家族の言葉は、その写真の引用があれば使い、なければ空のまま。問いかけは、固定の言葉にある開かれた一文
- 失敗を家族に知らせない。記録には「固定の入り口」の印を付け、ログに残す
- 一度家族に見せた入り口は、後から差し替えない
- 開いた時点で今日の入り口がなければ、その場で固定の入り口を作って保存する（その場で Claude を呼ばない）
- 文字起こしが失敗しても、録音は残す。文字の欄は空にして後でやり直す。文を作って埋めない

### 毎朝の処理
- 失敗した人だけ飛ばして、残りを続ける。処理全体を失敗にするのは、全員が失敗したときと、データベースにつながらないときだけ
- 終わりに、作れた人数、飛ばした人数、失敗した人の ID と理由の種類をログに出す
- 家族一人 × 日付で入り口は一つ。同じ日にもう一度呼んだら、足りない分だけ作る
- 全体を 10 分以内に終える（Cron の上限の内側）

## 3. Workers と逃げ道

- 迷ったら「Workers で楽になる書き方」より「VPS でも動く書き方」に倒す
- Node.js 専用のもの（`fs`、`path`、`child_process`、`Buffer`、`process.env`）を、アプリの中心で使わない。Web 標準（`fetch`、`ReadableStream`、`crypto.subtle` など）を使う
- 外の世界に頼るものは、すべて差し替えられる層を通す。データベース、写真・録音の保存に加えて、**Claude と文字起こしの呼び出しも**通す
- D1 や R2 でしか動かない機能を使う前に、better-sqlite3 とローカルのファイルで同じことができるかを考える。できなければ、Workers 専用の層の中に閉じ込める
- 「今日」は日本時間で決める（Workers は UTC で動く）
- つなぐサービスを増やさない。増やすなら decisions に残す

## 4. 入力と安全

- 外から受け取るデータは、境界で zod で検証する。HTTP のリクエストに加えて、Claude と文字起こしの応答も「外から来るデータ」として扱う。中心は検証済みの型だけを受け取る
- 検証に失敗したら、エラーの種類だけを返す。受け取った値を、応答にもログにも出さない
- **合言葉の確認は一か所にまとめ、既定で閉じる。** 確認しない入り口（ヘルスチェック、静的ファイル、合言葉の入力）を明示的に列挙し、それ以外はすべて確認を通す。写真・録音に加えて、語りや家族のデータを返す入り口も対象にする
- 合言葉なしの要求には 401 を返す。ほかの家族のものは、存在しないものとして 404 を返す
- 合言葉は平文で保存しない。比べるときは時間が一定の比較を使う。cookie は HttpOnly、Secure、SameSite=Lax にする
- 写真・録音を返すときは `Cache-Control: private, no-store` を付ける
- 手元とテストで触るのはデモの家族だけ。本番の D1 を手元に写さない

## 5. テストの考え方

- 壊れると困る順に守る
  1. 合言葉の確認（確認しない入り口の一覧をテストで固定する。増えたら気づく）
  2. 出所と推測が分けて保存されていること
  3. デモの初期化が、デモの家族の外に触れないこと
  4. 毎朝の処理とデモ用ボタンが、同じ関数を通ること
  5. VPS への逃げ道（中心が Workers 専用の API に頼っていないこと）
  6. Claude の応答の検査（スキーマ違反、試す言い回し、実在しない引用の ID を止めること）
- **`npm test` では、Claude も文字起こしも本当には呼ばない。** 偽物に差し替える。偽物は、合う応答と合わない応答の両方を返せるようにする
- 本物を呼ぶのは二か所だけ: 出し比べ（架空の家族）と、デプロイ後のヘルスチェック
- 同じ入力で二度呼んでも結果が一つになること（冪等）を確かめる。対象は、毎朝の処理、録音の受け取り、デモの初期化
