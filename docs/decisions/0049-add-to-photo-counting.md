# 0049 「この写真に追加する」の数え方と失敗の見せ方

- 日付: 2026-11-04
- 状態: 採用
- 決めた人: fable-advisor に相談（frontend-developer）。画面の言葉は人間（2026-11-04）

## 決めたこと
「この写真に追加する」（0048。アルバムの各写真の節の末尾、家族の画面だけ）のクライアントの細部。

- 「追加した写真 n枚」は、応答の `link.linked` が true の枚数。棚に既にあった同じ写真（`duplicate`）でも、今回この写真につながれば追加に数える（列にも新しく現れる）
- 「すでにある写真」は `link.linked` が false（すでにこの写真とつながっていた）。`link` が null の 2xx（この流れでは起きないはず）は「送れなかった写真」に数える。「読めなかった写真」「送れなかった写真」は写真を共有する画面と同じ
- 「はずす」は、今回の応答で得た (musubiId, photoId) だけを一枚ずつ外す。読み直した `addedPhotos` に混ざるほかの家族がつないだ写真は対象にしない。一部が外せなかったら、外せた分は列から消し、残りは列と「はずす」を残して、エラーの文を一行だけ出す。404（もう無い）は外れたとみなす
- 送る途中でリンクが切れた（401）ら、残りを送らずに止め「リンクを開きなおしてください」。ほかの失敗は「送れなかった写真」に数えて続ける（写真を共有する画面と同じ）
- 終わった後・外した後は /api/feed を読み直して `addedPhotos` をサーバーの値にそろえる。アルバムの並びは変えない（Home の albumOrder）
- 送る道（EXIF → ハッシュ → 縮小 → 送る）は写真を共有する画面と一つにする（src/client/lib/upload.ts）
- ボタンの語は「この写真に​追加する」。幅 360px・文字 150% で一行に入るよう横の余白を詰め（0.5rem）、入らないときは言葉の切れ目でだけ折る（何もしないと「この写真に追加す／る」と最後の一文字が落ちた）

## 理由
- この文は列のすぐ下に出るので、列に現れた枚数と一致していることが第一（requirements「家族に見せる言葉は事実を中心に、作り話をしない」）。「すでにある」は、この写真の節の中に出る以上「この写真にすでにある」と読まれるので、写真を共有する画面の「棚にすでにある」とのずれは小さい
- 外した結果は、画面が今の状態をそのまま映す。全部消せるまで列を変えないと、押したのに何も変わらない時間ができ、何が残ったか見えない
- 他人がつないだ行は 404 で消えないので、対象に含めると押した人には「はずせなかった」に見える

## 退けた案とその理由
- 写真を共有する画面と同じ数え方（`duplicate` なら「すでにある写真」）: 棚にあった写真が今回つながって列に新しく現れても「すでにある写真 1枚」と出て、目の前の列と数が食い違う
- 「はずす」を全部消せるまで列を変えない: 何が残ったか見えない

## 根拠にしたもの
- src/shared/api.ts の UploadPhotoResult.link、DELETE /api/musubi/:musubiId/photos/:photoId（ce1f1b5）
- 高さ（2026-11-04、手元の playwright の電話の画面。部品を react-dom/server で描いて styles.css を当てた画面で、追加の節がある・ないを比べた）: 家族・祖父母 × 360・375 × 640・667 × 文字 100・130・150% のすべてで、語りの欄の高さ（640: 376・382・405、667: 377・369・408。0041 の表と同じ）と、見出しの上端から「返事」の下端までの高さが、追加の節の有無で変わらない。横のはみ出しなし。祖父母の画面には追加の節を描かない

## 見直す条件
- 「すでにある写真」の意味の違いに家族から戸惑いの声が出たら、この画面の語だけ人間に替えてもらう（語は人間が決める）
- 「はずす」を一括の API にしたら、一部失敗の話は消える
