# 0009 初日の時間の扱いと、語りの受け取りの冪等

- 日付: 2026-11-02
- 状態: 採用
- 決めた人: fable-advisor に相談（backend-developer）。時計を使える家族の範囲（本番ではデモの家族だけ、手元・プレビューではどの家族も）は人間

## 決めたこと

- Cron（毎朝）は、時計を持つ家族（`families.clock_date` が非 null）を飛ばす。その家族の朝はデモの時計のボタンでだけ来る。どちらも同じ `runMorning` を通る
- 時計を持たない家族の「今日」は日本時間の暦の日付。時間帯は 0:00–10:59 朝、11:00–16:59 昼、17:00–23:59 夜。時計を初めて進めるときは、今の日付・時間帯を起点にする
- 時計を使えるかの判断は `core/clock.ts` の `canAdvanceClock` 一か所。`APP_ENV` が `production` のときだけデモの家族に限る。`APP_ENV` がなければ本番とみなす
- 固定の入り口で、その人にまだ出していない写真がないときは、その人に最後に出したのがいちばん古い写真をもう一度出す。写真が一枚でもあれば入り口は必ず作る。「まだ出していない」は、その人の入り口について判断する
- 語りの受け取りは、クライアントが語り一つごとに作る `requestId`（UUID、任意）で再送を見分ける。`(family_id, request_id)` を一意にし、再送には作ってある語りを 202 で返す。先に届いたものが勝ち、中身は比べない

## 理由

- デモの進行は見せる人が完全に握る。入り口を作る経路を一つにし、デモと本当の日付の入り口が混ざらないようにする
- 「今日」の定義を一つにする（Cron・語り・入り口で食い違わせない。implementation-policy 3）
- 毎朝届くことを優先する。入り口がない画面は、結果として写真を求める形になる（requirements「写真を求めない」）
- 冪等は文字の語りにも効く形にし、Web 標準だけで VPS でも同じに動かす

## 退けた案とその理由

- Cron が時計の日付で入り口を作る: デモの進行が見せる人の手を離れる
- 5:00 を一日の始まりにする: 「今日」の定義が二通りになる
- 写真が尽きたら入り口を作らない: 届かない朝ができる
- 録音の SHA-256 で再送を見分ける: 本体を全部読む必要があり、文字の語りに効かない。同じ声を二度録ることは普通にある

## 根拠にしたもの

- docs/requirements.md、docs/implementation-policy.md 2・3・5

## 見直す条件

- 本番で本物の家族に時計を持たせる必要が出たとき（先に時計を null に戻す操作を用意する）
- 深夜（0:00–5:59）に開いた本物の家族に、固定の入り口ばかり届くと分かったとき（先に Cron の時刻を疑い、日付の定義は動かさない）
- フロントが `requestId` を必ず送るようになったら、必須にする
