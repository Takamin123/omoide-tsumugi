# 0033 家族のことの画面に家族の番号を出す

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: 出すことは人間の指示。言葉と見せ方は fable-advisor に相談（frontend-developer）

## 決めたこと
- `/family` の一番下、招待リンクの節の下に区切りの線を置き、補助の文字（.sub）で「家族の番号」と家族 ID（UUID）を出す。h2 の節にせず、ボタンも付けない
- UUID の行は招待リンクと同じ見え方（`.invite-url`: 補助の文字の大きさ、本文と同じ書体、`user-select: all`、折り返し）。等幅にしない
- 言葉は `words.family.familyIdLabel = "家族の番号"`。説明の文は付けない
- サーバーは変えない（合言葉の cookie で守られた `GET /api/family` の `view.family.id` をそのまま出す）。祖父母の画面には出さず、祖父母の画面から `/family` へ動かす道も作らない（`/family` へ動かすのは家族の画面 Home だけ。テストで固定）

## 理由
- 運営が本番で家族 ID を知る道が要る（0030 の OPS_RECORD_FAMILIES、0031 の消す手順）。家族 ID は鍵ではなく（記録は OPS_RECORD_TOKEN、消すのは wrangler のログイン）、出す場所は合言葉の内側だけ
- 「番号」は英字の専門語を避けた語（implementation-policy「家族に見せる言葉」）。ラベル一語で意味を与え、説明の文で仕組みや窓口を前に出さない
- 一度触れれば全体が選べるので、画面の写し（家族の名前が写る）ではなく文字だけを送ってもらえる

## 退けた案とその理由
- 「この家族の ID」: 英字の専門語
- ラベルなし: 意味の分からない文字列が不安に見える
- 「問い合わせ用の番号」: 窓口があるように見える
- 「写す」ボタン: 同じ画面に「写す」が二つ並び、押せるものが増えて主な動作がぼやける
- 等幅書体: UUID は小文字の 16 進で読み違いが起きにくく、等幅は目立つ

## 根拠にしたもの
- fable-advisor との相談（2026-11-03）
- docs/requirements.md「プライバシー」、docs/implementation-policy.md「家族に見せる言葉」、0030、0031

## 見直す条件
- 家族自身がこの番号を使う場面ができたとき（人間が決める）
- 電話で読み上げてもらう必要が出たとき → 区切りや等幅を考える
- 「これは何」と聞かれたとき → 仕組みの言葉を使わない一文を足す
