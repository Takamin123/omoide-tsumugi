# 0033 家族のことの画面に家族の番号を出す

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: 出すことは人間の指示。言葉と見せ方は fable-advisor に相談（frontend-developer）

## 決めたこと
- `/family` の一番下、招待リンクの節の下に区切りの線を置き、補助の文字（.sub）で「家族の番号」と家族 ID（UUID）を出す。h2 の節にしない
- その下に「番号を写す」ボタン（押すとクリップボードに写し、「写しました」に変わる）。招待リンクの「写す」と見分けるため目的語を付ける（2026-11-03、人間が実機で試して決めた）
- UUID の行は補助の文字の大きさ、本文と同じ書体、折り返し（`.family-id-value`）。等幅にしない
- 長押しで全部選ぶ設定（`user-select: all`）は使わない。Android の Chrome では、付けると選択がすぐ外れ、外すと UUID の一部しか選べず「タップして検索」の帯が出た（2026-11-03、人間が iPhone と Android の実機で確かめた）
- 言葉は `words.family.familyIdLabel = "家族の番号"`。説明の文は付けない
- サーバーは変えない（合言葉の cookie で守られた `GET /api/family` の `view.family.id` をそのまま出す）。祖父母の画面には出さず、祖父母の画面から `/family` へ動かす道も作らない（`/family` へ動かすのは家族の画面 Home だけ。テストで固定）

## 理由
- 運営が本番で家族 ID を知る道が要る（0030 の OPS_RECORD_FAMILIES、0031 の消す手順）。家族 ID は鍵ではなく（記録は OPS_RECORD_TOKEN、消すのは wrangler のログイン）、出す場所は合言葉の内側だけ
- 「番号」は英字の専門語を避けた語（implementation-policy「家族に見せる言葉」）。ラベル一語で意味を与え、説明の文で仕組みや窓口を前に出さない
- ボタンで写せば端末によらず全体が写せ、画面の写し（家族の名前が写る）ではなく文字だけを送ってもらえる

## 退けた案とその理由
- 「この家族の ID」: 英字の専門語
- ラベルなし: 意味の分からない文字列が不安に見える
- 「問い合わせ用の番号」: 窓口があるように見える
- ボタンなし、長押しで選ばせる（はじめの形。fable-advisor は「写す」が二つ並ぶのを避けた）: Android の実機で全体を選べなかった。ボタンの語を「番号を写す」にして見分ける
- 共有ボタン（navigator.share）: 運営が自分で写せれば足りる。共有の一覧から送り先を選ぶ手間が増える
- 等幅書体: UUID は小文字の 16 進で読み違いが起きにくく、等幅は目立つ
