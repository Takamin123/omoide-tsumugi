# 0026 記録の画面は「日付と人で見る」と「写真で見る」の二つの見方にし、家族の言葉だけを明朝にする

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: 人間（Claude Design に描いた案 A・B から選び、レビューで書体・色・枠の決まりを決めた）。実装は frontend-developer

0025（記録の画面は運営・開発用、運営の鍵で守り、本番では出さない）はそのまま。ここでは見せ方と、そのために API に足したものだけを決める。

## 決めたこと
- 見方は二つ。既定は「日付と人で見る」（日付を選び、人ごとに 1. 材料にした語り、2. 今日の入り口、3. 返ってきた語り）。もう一つは「写真で見る」（写真の一覧、選んだ写真と各入り口の focus の枠、写真の説明、この写真がたどったことの時系列）
  - 返ってきた語りは、その入り口の entranceId を持つ語り
- URL に family、view（photo のときだけ）、date、photo と、語りの欄のアンカーを載せ、再読み込みと戻る・進むで保つ。鍵は載せない（0025 のまま sessionStorage だけ）
- 枠は三種類だけ: 家族が語った言葉は青の実線、Claude が決めたこと・推測は茶の点線、家族の画面に出た形は墨の実線。凡例は一度だけ出し、箱ごとのラベルは並べない。区切りは太い罫線と見出し
- 書体は、家族が語った言葉（transcript、引用、材料と返事の本文）だけを明朝、ほかはゴシック。Claude が整えた文（cleaned_text）は明朝にしない。外のフォントは読み込まず、端末の書体のスタックを使う
- API（GET /api/ops/families/:familyId/record）に、写真の登録時刻（photo.createdAt）と声の長さ（narration.durationMs）を足す。緯度経度・保存先のキー・録音は返さないまま

## 理由
- 「入り口が平板でないか、理由が妥当か、focus がずれていないか」（0025 の目的）は、その日の人ごとの流れで見る場面と、一枚の写真の来歴で見る場面の両方がある
- 色と線の種類の両方で分けると、出所つきの語りと推測が混ざって見えない（requirements「記録と言葉」）。明朝を家族の言葉だけにすれば、文字の形でも分かれる
- つなぐサービスを増やさない（implementation-policy 3）

## 退けた案とその理由
- 案 C（語った・決めた・見えたの三列の対応表）: 人間が A・B を選んだ
- Google Fonts で書体をそろえる: つなぐサービスが一つ増える
- 枠の上に「日付 人」の名札をそのまま付ける（写真で見る）: 枠が近いと名札が重なって読めない。枠には番号だけを付け、日付と人は写真の下に一覧で出す
