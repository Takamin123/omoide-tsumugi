# 0057 前の日に出した写真を、次の日の入り口に続けて出さない

- 日付: 2026-11-05
- 状態: 採用
- 決めた人: 人間（2026-11-05。案 B）。0 枚になるときの倒し方と固定の入り口の扱いは backend-developer がコードを見て判断（下に記す）

## 決めたこと
- 前の日（forDate の 1 日前）にこの人の入り口に出した写真は、次の日の Claude の入り口の候補（pickEntranceCandidates）にしない。日数は定数 ENTRANCE_NO_REPEAT_DAYS = 1（src/server/core/entrances.ts）
- 例外は g0（ほかの家族が、この人の語りに返事をした写真で、その返事の後にまだ出していないもの。0042）だけ。g0 は前の日に出していても候補に残す
- g1a・g1・g2・g3・g4 からは外す。実際に効くのは g1 だけ。g1a はもとから前の 7 日に出した写真を入れない（0046）、g2・g3 は未出のもの、g4 は 7 日たったもの
- 外すと候補が 0 枚になるとき（backend-developer の判断）:
  - 家族の写真がすべて前の日に出したもの（写真が 1 枚の家族）なら、外さない。Claude の入り口を作る
  - ほかに写真があれば、0 枚のまま返す（no_candidates）。毎朝の処理は固定の入り口に倒れ、固定の入り口が前の日の写真を避けてほかの写真を出す。前の日の写真は、その次の日に g1 で出られる
  - 外す順は「前の日の写真」が先、「今日ほかの人に出した写真」（0042）が後。後者は今までどおり、外すと 0 枚なら外さない
- 固定の入り口（pickFixedPhoto）も、前の日に出した写真をほかにあれば選ばない。写真がそれしかなければ出す。もとの選び方（未使用を先に、すべて使ったら最後に出した日のいちばん古いもの）では、一人に一日一つの入り口なので、前の日の写真が選ばれるのは写真が 1 枚のとき（か、今日より後の日付の入り口があるとき）だけ。ふだんの選び方は変わらない。明示の守りとして足した

## 理由
- 本番の親の試しで、家族の画面の人に、前の日（11/4）に出した写真が今日（11/5）も Claude の入り口として出た。前の日にその人に出した後、ほかの家族 2 人がその写真に語り（返事ではない）を残したため、g1（ほかの家族が語った写真で、その語りの後にこの人の入り口に出していないもの）に入って先頭に来た。受け取る側には「昨日と同じ写真」にしか見えない
- g0 は、その人の語りへの返事という、その人のためだけの材料（0042）。前の日の写真でも、返事が来たことは受け取る人に意味がある
- 0 枚のときに外さない（0042 の avoidPhotoIds と同じ倒し方）にすると、写真が少なく前の 7 日に全部出し終えた家族では、g1 に残るのが前の日の写真だけになり、今回の不具合がそのまま起きる。固定の入り口があるので、外しても入り口が作れなくなることはない。写真が 1 枚の家族だけは、固定でも同じ写真になるので、Claude の入り口を残す

## 退けた案とその理由
- A 今のまま（g1 は前の日に出していても先頭に来る）: 受け取る人には昨日と同じ写真にしか見えない。家族の言葉が届く道（翌日の入り口）が、届いたように見えない
- 0 枚なら外さない（avoidPhotoIds と同じ）: 上の理由のとおり、写真の少ない家族で同じことが起きる
- 前の日の写真を 7 日の除外と同じく g1 でも外す（日数を 7 にする）: 家族の語りが翌日に届く道（0017 の g1）を一週間止めることになる。人間の決定は「前の日」

## 根拠にしたもの

- デモの家族の撮影の朝の候補（0038 の追記の筋）: 種（src/server/demo/seed.ts）から組んだ行で、変更の前後の 4 人の候補の並びが同じ（test/entrance-no-repeat.test.ts）。じいちゃんの前の日の入り口 E4（Y1）は、n10 が E4 より前なので、もとから g1 にも g4 にも入っていない。じいちゃんの先頭は P8 のまま
