# 0055 LINE から開いたリンクは、いつものブラウザで開く

- 日付: 2026-11-04
- 状態: 採用（親の試しの途中に入れる）
- 決めた人: 人間（2026-11-04。リンクに付ける・LINE の中なら一行出す）。実装は Claude（メインの会話）

## 決めたこと
- 「家族のこと」で作る招待リンクに `?openExternalBrowser=1` を付ける（`inviteUrl`）。LINE で押すと、LINE の中の画面ではなく、いつものブラウザ（Android は Chrome、iPhone は Safari）で開く。LINE 以外のアプリでは意味を持たず、`/join/<token>` の読み取り（道すじだけを見る）も変わらない
- マイクが使えなかったとき、Android の LINE の中の画面（UA に `Line/` と `Android`）なら、「マイクが使えません」の代わりに「LINE の中では録音できません。右上の︙のメニューから、ブラウザで開いてください」を出す（祖父母・家族の両画面）。iPhone の LINE はマイクが使えるので含めない
- 作り直す前のリンクには付かない。今のリンクは、手で `?openExternalBrowser=1` を付けて送り直せば同じ効き目になる（作り直しは要らない）

## 理由
- 親の試しの初日、らくらくスマホ（Android）で LINE から開いたリンクで「はなす」を押すと、マイクが使えなかった。同じリンクを iPhone の LINE から開いたときは使えた。Android の LINE の中の画面はページからのマイクの求めを通さないことが多い
- LINE の中で開くと、入った記録（cookie）も LINE の中にしか残らない（parent-trial の手順で「Chrome で開いて」と案内していたこと）。いつものブラウザで開けば、ホーム画面にも足しやすい

## 退けた案とその理由
- 案内だけで済ませる（「Chrome で開いて」と伝える）: 親が毎回 LINE から開く使い方では、毎回メニューを選ぶ必要がある
- LINE の中の画面を見分けたら、すぐにいつものブラウザへ移す: 移すための確かな方法がこの仕組みのほかにない

## 見直す条件
- LINE が `openExternalBrowser` をやめた、または効かない端末があった
- iPhone で Safari に移ることが、かえって戸惑いになった

## 補足
- 祖父母の画面のこの文は、エラーの文はひらがなという決まり（words.ts の注、0028）の例外として漢字まじりにした。0050 で人間が「ひらがなだけだと逆に読みづらい」と言ったことに合わせ、「録音」「ブラウザ」など読み慣れた語をそのまま使う
- LINE のメニューの項目の名前（「ブラウザで開く」「他のアプリで開く」など）は版や端末で違いうるので、字どおりの名前は書かず「︙のメニューから、ブラウザで開いてください」とした
