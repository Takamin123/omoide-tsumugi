# 0031 家族の場を消す手順は運営の wrangler のログインだけで行い、アプリに消す入り口を作らない

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: fable-advisor に相談（backend-developer）。消す約束そのもの（1 週間以内、家族の場ごと全部）は人間（0027）

## 決めたこと
- 手順は `.claude/skills/delete-family/SKILL.md`、処理は `scripts/delete-family.mjs`。wrangler の getPlatformProxy に remote のバインディング（D1 と R2）を渡し、運営の手元の wrangler のログインだけで本番・プレビューに触れる。手元は `.wrangler/state` のバインディングで同じ関数を動かす
- 消すもの: D1 のその家族の全部の行（全部の表に family_id がある。外部キーの子から、一つの batch で）と、R2 の接頭 `families/<id>/` の全部のファイル（接頭で一覧して消すので、D1 の行が指していないファイルも消える）
- 順番: 数える → D1 の行（storage_key / audio_key / question_audio_key）が指すキーが接頭の外にないか確かめる（あれば何も消さずに止める）→ D1 を消す → R2 を接頭で消す → 数え直して 0 件を確かめる。途中で落ちても、もう一度打てば続きから消える
  - D1 を先にする（fable-advisor の下書きは R2 が先）: families の行が消えた時点でアプリの合言葉が通らなくなり、新しい書き込みが止まる。R2 は接頭で掃くので、D1 の行がなくても消せる
- 守り: 家族 ID は UUID の小文字の完全な形だけ。接頭は必ず末尾のスラッシュ込み（`families/` だけで一覧しない）。消すときは `--confirm` に同じ ID をもう一度書く。デモの家族は `--allow-demo` なしでは消さない（デモは demo-reset の道）。プレビューと本番が同じ D1 か R2 を指していたら止まる
- 出すのは環境・家族 ID・デモかどうか・件数だけ。名前、語りの本文、R2 のキー、URL は出さない。家族 ID もファイルに書かない
- 本番で消すのは、人間の確認の後に人間が自分の端末で打つ。スクリプトは本番で消すとき、端末からの入力がなければつなぐ前に止まり、件数を見せた後に家族 ID をもう一度打たせる（Claude やサブエージェントからは仕組みとして消せない）。サブエージェントは本番では数えるまで
- ほかの家族の行がこの家族の接頭の下のキーを指していたら、何も消さずに止める（今の書き込みでは起きないが、接頭ごと消すので逆向きも確かめる）。local では、wrangler.jsonc に remote のバインディングがあれば止める
- 本番で使う前に、preview でデモでない使い捨ての家族を一度消してみる。本番の初回は、人間が Cloudflare のダッシュボードでも接頭 0 件を確かめる
- 消した後、`OPS_RECORD_FAMILIES` から ID を外す（0030）
- 本人に伝えるときは、作り手の言葉で「Cloudflare のバックアップ（D1 の Time Travel）に保持期間のあいだ残り、その後は自動で消える」と添える。作り手が Time Travel で戻すことはしない
- remote のバインディングが動かなくなったときの退路: wrangler の CLI で、D1 から集めたキーを一つずつ消す（孤児は残りうるので、ダッシュボードで確かめる）

## 理由
- requirements「プライバシー」。実際の家族のデータに触れる道は少なく保つ。0025、0030 と同じく「鍵一つが漏れたときの被害」で測る。この形は、運営がすでに持つ wrangler のログインの範囲で動き、新しい鍵・入り口・設定を足さない
- 0027「家族の場ごと全部」に、接頭ごと消す形がそのまま一致する。D1 に載らないファイル（put の後に D1 の書き込みと後始末の両方が失敗したときなどに、まれにできうる）も消え、0 件を一覧で確かめられる
- D1 を一つの batch で消すので、半分だけ消えた状態が残らない
- 手元・プレビュー・本番で同じ関数が動き、プレビューでの予行が本番と同じ道の確かめになる
- 「作り話をしない」を、作り手が本人に言う言葉にも当てる

## 退けた案とその理由
- wrangler の CLI だけで、D1 から集めたキーを一つずつ消す: wrangler 4.156 の `r2 object` に一覧がなく、D1 に載らないファイルを消せず、0 件を確かめられない。写真が数百枚だと数百回呼ぶ。退路として残す
- R2 のライフサイクルの規則で接頭を掃く: 実際の家族の ID がバケットの設定に残り、外し忘れが残る。消えるまで最大 1 日かかり、伝える時点で確かめられない。手元で試せない
- S3 互換の鍵で接頭ごと一覧・削除: 全バケットに届く鍵が運営の手元に増える。まだ発行していない
- アプリに運営の消す入り口を作る（別の鍵）: 本番に「鍵一つで実際の家族を消せる」道ができる。漏れたときの被害が一番大きい
