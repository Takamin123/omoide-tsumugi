# 0051 裏から前に戻ったときに、今日の入り口と家族の語りを読み直す

- 日付: 2026-11-04
- 状態: 採用
- 決めた人: 人間（2026-11-04）

## 決めたこと
- 家族の画面・祖父母の画面（Home）で、アプリが裏から前に戻ったとき（document の visibilitychange で visible、pageshow の persisted）に、次のどれかなら今日の入り口（/api/entrances/today）と一覧（/api/feed）を読み直す
  - 最後に入り口を読めた時から、日付が替わった。日本時間の暦日で、実時間で比べる（家族の「今日」はサーバーが決める。デモの家族の時計は別の仕組み）
  - 日付が同じでも、裏にいた時間が 10 分以上（ほかの家族の新しい語り・返事を出す）
- 話している・書いている途中（録音中・マイク待ち・文字の欄・返事の欄・「とりなおす」の録り直し中・答えを送っている間・送れなかった答えを持っている間）は読み直さない。読み直しの最中に話し始めたら、届いた結果を捨てる（前のものを残し、次に前へ戻ったときにまた判断する）。終わった後に改めて読み直さない（次に前へ戻ったときでよい）
- 前に出ている間の定期的な読み直しはしない
- 読み直しは静かに行う。「読み込み中」に戻さず、今の写真を出したまま届いたら差し替える。読めなかったときは黙って前のものを残す（失敗の文を新しく出さない）
- 入り口が替わったら、前の入り口に結びついた手元の状態（この画面で答えた印、「送りました」「おくりました」、「とりなおす」）を消す
- アルバムのタブで読み直しても、帯の並びと今見ている写真は動かさない
- サーバーは変えない。判断は src/client/lib/useResumeRefresh.ts

## 理由
- ホーム画面に置いたアプリを夜に裏へ回し、朝に前へ戻すと、前の日の入り口のまま残る。親（らくらくスマホ・タブレット）の試しで起きやすく、祖父母は開き直すことを知らない
- 途中のものを壊さないことを、新しいものを出すことより先にする（話している途中に写真が替わると、何に答えていたかが分からなくなる）

## 退けた案とその理由
- 前に出ている間の定期的な読み直し: 見ている写真が勝手に替わる
- 読み直しの間「読み込み中」で消す（開いたときと同じ流れ）: 前に戻るたびに画面がちらつく

## 根拠にしたもの
- 人間の決定（2026-11-04）
- src/client/screens/Home.tsx の開いたときの読み込み（me.id・attempt）

## 見直す条件
- 前に戻っても新しい語りが出ないと家族から言われたとき（10 分を短くする）
- 前に戻るたびの読み直しが通信量や電池で問題になったとき
