# 0039 記録の取り出し（extract_records）

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: fable-advisor に相談（backend-developer）。流れは人間が承認（2026-11-03）

## 決めたこと

### いつ、何を材料にするか
- 毎朝の処理（runMorning）の家族ごとのループで、runPhotoGuesses の後・入り口づくりの前に `runRecordExtraction(deps, familyId)` を呼ぶ。背景処理には入れない。Cron とデモの時計のボタンは同じ関数を通る（0009）
- 材料はその家族の未処理の語り。声は quoteSource が取れるもの（使える cleaned_text）だけ、文字は transcript。未整形の声は飛ばして翌朝に回す。返事も対象
- Haiku（claude-haiku-5-5）に渡すのは、語り手の呼ばれ方、家族の呼ばれ方の一覧、表示の文字（displayText。印の範囲は「……」）、返事なら相手の語り（`quotable="no"` の文脈。ここからは抜かない）。画像、photo_guesses、撮影日、位置、ID は渡さない
- 一語りに一回の呼び出し。Batch は使わない。順番に回し、時間の予算 60 秒（定数）を超えた語りは呼ばずに翌朝に回す

### 出力と保存
- 構造化出力 `{ records: [{ kind: person|place|time|event, text }] }`。text は語りの本文から一字も変えずに写した連続した部分。正規化しない。空の配列を許す
- 位置は Claude に返させず、アプリが locateQuote で決めて records.quote_start / quote_end に入れる
- records に origin = told、told_by_member_id = 語り手、narration_id、photo_id = その語りの写真、model / prompt_version は NULL（records_origin の CHECK）で入れる
- 作業の表 record_extractions（PK narration_id、family_id、prompt_version、model、state done|failed、attempts、input / output tokens、created_at）。0 件でも done を残す（冪等）。プロンプトの版が上がっても取り直さない。records は done の行がまだないときだけ、作業の行の done と一つの batch で入れる
- failed は attempts が 3 回に届くまで翌朝に取り直す。キーがない（not_configured）、時間の予算で呼ばなかった、使える文字がなかった語りは、作業の行を残さない

### 検査（全か無か。違反は 1 回だけ再試行）
- kind が列挙の中（スキーマ）、text が空でない、text は 30 字以内、件数は 12 件以内（どれも定数）
- locateQuote で見つかり、印の範囲と重ならない（違反の種類は not_found / uncertain_overlap）。同じ範囲の重複なし
- 値が代名詞・指示語だけのものを止める（定数: あんた、あなた、わし、わたし、私、あの人、あそこ、ここ、そこ、これ、あれ）

### プロンプト（src/server/prompts/extract_records/v1.md）
- 裏の整理係。語りの言葉そのままを抜く。言い換え・補完・代名詞の解消・名前の推定・写真の内容の想像をしない。「たぶん」「〜か〜か」のまま抜く。「……」を含む範囲は抜かない
- kind の線: 行事名は event、年号・季節・年齢・「〜の頃」は time、場所の語は place、人を指す名前・続柄・呼び名は person（代名詞は除く）。ない種類は返さない、迷ったら返さない
- 出し比べの 1 回目で「あそこの家」を place に入れた（2 回のうち 1 回）ので、「指す先の決まらない言葉で始まる人や場所も抜かない」を v1 に足した（本番で使う前）。足した後の 2 回では出なかった
  - 足す前の n04（じいじ「この犬はあれよ、ほら、あそこの家の。…あの人よ、川の向こうに住んどった。…」）の出力: 1 回目 place:「川の向こう」、2 回目 place:「あそこの家」 place:「川の向こう」

### そのほか
- 作業の行は、語りがその家族のものであるときだけ入る（insert … select … from narrations where id と family_id）。records も同じ
- 家族の削除（scripts/delete-family.mjs）の表の一覧に record_extractions を入れる（records より後、narrations より前）
- ログは ID・件数・所要時間・トークン数・違反の種類だけ。本文と取り出した値は出さない

## 理由
- 家族が語ったことと Claude の推測を分ける（requirements、0010）。本文そのままの部分なら、出所（誰の、どの語りの、どこ）がそのまま付き、told として持てる。正規化（「昭和五十三年」→ 1978）は Claude の推測なので told に入れない
- 位置をアプリが決めるのは、入り口の引用と同じ考え（0017、0023）。Claude に位置を数えさせると外れる
- 朝の処理に置くと、Cron とボタンが同じ経路になり、未整形の声も翌朝には整形済みになっている。背景処理（整形の直後）は waitUntil の 30 秒に Claude の呼び出しを二つ重ねることになる
- 一語り一回は、失敗が一つの語りに閉じ、検査の違反の再試行も一つの語りで済む。家族の語りの数は一日に数件で、Batch の半額を待つ（最長 24 時間）理由が今はない
- 版ごとに取り直さないのは、本文そのままの抜き出しは版で意味が変わりにくく、取り直すと同じ語りの記録が版ごとに重なる（どれを使うか決める仕組みが要る）ため

## 退けた案とその理由
- 整形の直後の背景処理で取り出す: waitUntil の 30 秒の内側に整形と取り出しの二つの呼び出しを収める必要がある。経路が朝の処理と二つになる（0009 の考えに反する）。文字の語りは整形を通らないので、別の入り口がもう一つ要る
- 家族の語りをまとめて一回で頼む: 一つの語りの違反で全部がやり直しになる（全か無か）。どの語りの記録かを Claude に ID で返させることになり、取り違えを検査で見つけにくい
- 正規化した値（年号の西暦、場所の正式名）を told に入れる: 家族が語っていない値が「家族が語ったこと」として残る。要るなら guessed の行として別に足す
- プロンプトの版が上がるたびに取り直す: 記録が版ごとに重なり、使う側で選ぶ仕組みが要る。費用も版の数だけかかる

## 根拠にしたもの
- 出し比べ: docs/evals/2026-11-03-records.md（evals/records.eval.ts、架空の家族 family-a の 10 語り × 2 回）。足した後の結果は、20 / 20 取り出せた、再試行 0（検査の違反なし）、person / place に「あの人」「あそこ」を含むもの 0、短い語り（「わしの車じゃ。」）は 2 回とも空、聞き間違いの印（交番、お仲間さん）は一度も抜かなかった、食い違う返事（n06、n07）はそれぞれ自分の本文の語だけを抜いた、「たぶんお父さん」はそのまま。一語り 1〜6 秒（中央 3.8 秒）、入力 約 1,600 トークン・出力 約 500 トークン
- Workers の上限: サブリクエストは無料 50・有料 10,000（D1 も数える）。一語りあたり Claude 1〜2 回と D1 数回なので、60 秒の予算の内側（十数語り）なら有料プランで余裕がある（https://developers.cloudflare.com/workers/platform/limits/ 、0021 で 2026-11-03 に確認したもの）

## 分かっている性質（出し比べから）
- 同じ語りでも、2 回で記録の組が違うことがある（10 語り中 4 語り。kind は揺れず、抜く範囲と数が揺れる）。語りどうしをつなぐ側は、この揺れを前提にする
- 範囲が入れ子の記録（「隣の町」と「隣の町の校長先生」）は両方入る（検査が止めるのは同じ範囲だけ）
- time の「あの頃」「この頃」は通る。指す先は決まらないが、「〜の頃」は time とする線に合わせた

## 見直す条件
- 未処理の語りが一度に 30 を超える日が普通になったとき（Batch を考える）
- むすびの推測に時期の正規化が要ると分かったとき（guessed の行として足す）
- 朝の処理で past_deadline（入り口の予算切れ）が出たとき、または取り出しの deferred が続くとき（予算と順番を見直す）。入り口の予算（7 分）は runMorning の始まりから数え、家族ごとに写真の説明（最大 60 秒）と取り出し（最大 60 秒）が先に走るので、Cron で回す家族が 4 つ前後を超えると後ろの家族の入り口が固定になりうる
- デモの時計のボタン（runMorning を待ってから返す）の待ちが、前日の語りの数だけ延びる（一語り 1〜6 秒）。撮影で気になったら考え直す
- 使える文字がなく飛ばした語り（壊れた印の範囲など）と処理の途中で投げた語りは作業の行を残さないので、翌朝も先頭に残る。一回に見る上限（50）がそれで埋まることが起きたら、飛ばしたものにも印を残す
- 「昭和の五十…三年」のように本文にもともと「…」がある語りで、時期が途中で切れて抜かれる（出し比べ n01）。手がかりとして足りないと分かったら、プロンプトで「……」（聞き取れなかった所）と本文の「…」を分けて書く
