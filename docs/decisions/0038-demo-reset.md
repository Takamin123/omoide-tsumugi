## 決めたこと

### 入り口と鍵
- `POST /api/demo/families/:familyId/reset`、`Authorization: Bearer <DEMO_RESET_TOKEN>`。運営が家族の ID を明示する
- 鍵の確かめは routes/auth.ts の一か所（`/api/demo/families/` の下は合言葉ではなく初期化の鍵）。運営の記録の鍵（0030）と同じ規則: 32 文字未満、CREATE_FAMILY_TOKEN・OPS_RECORD_TOKEN と同じ値なら「設定なし」とみなして誰も通さない
- その家族がない・is_demo が偽なら 404（何も変えない）。環境では分けない（本番でもデモの家族だけを戻せる）

### 残すもの・戻すもの
- 残す: families の行（時計のほか）、members、invite_links。一行も書かない
- 戻す: photos・narrations・entrances・photo_guesses・photo_guess_requests・records・record_extractions・musubi・musubi_photos・musubi_guess_runs（0044 で足した）と、それらの行が指す R2 のファイル（families/<id>/ の下だけ）
- 時計は、初期化した日（日本時間。種の asOfDate）の朝
- D1 の「消す＋入れる＋時計」は一つの batch。種のファイルは batch の前に families/<id>/ の新しい鍵へ写し（get → ArrayBuffer → put）、古いファイルは batch の後に消す。何度呼んでも同じ状態（ID のほか）

### 種
- 台本（人間が承認）は src/server/demo/seed.ts に、文を変えずに置く。家族 4 人・写真 12 枚・語り 12 本・固定の入り口 2 つ・返事。語りの日は「asOfDate の何日前」、時刻は日本時間で、その日の入り口の後
- 人は呼ばれ方で指す。家族の人の呼ばれ方と role が種と一致しない（人数・重なりを含む）ときは、何も変えずに 409 demo_seed_mismatch（名前は返さない）
- 写真と録音のファイルは R2 の demo/seed/ に置く（リポジトリに入れない）。欠けている・種類が違うときは、写した分を消して 409 demo_seed_missing
- 写真の content_hash・幅・高さは種のファイルから計算して書く。撮影日は台本の表の日時。位置は持たない（→ 2026-11-04 追記で、架空の公開の代表点を持つ）
- 過去の入り口は kind='fixed'（question・model・reason は null）。添える言葉は語りの ID と範囲（範囲は初期化のときに quoteSource の中で台本の文字を探す）
- 声の語りの transcript は台本そのまま。cleaned_text・uncertain_spans・cleaned_model・cleaned_prompt_version は、本物の Haiku を一度呼んだ結果を写す（evals/demo-seed-clean.eval.ts が src/server/demo/seed-cleaned.ts を書く）
- 声の録音の長さは、録音を置くときに測って seed.ts に書く。測るまでは null
- photo_guesses・records は種に入れない。最後の毎朝の処理が作る

### 最後と返すもの
- 最後に runMorning(deps, now, { familyId, photoGuess: { noBatch: true, budgetMs: 90 秒 } }) を呼ぶ（Cron・時計のボタンと同じ関数）。全員が失敗しても初期化は済んでいるので、morning を null にして 200
- 写真の説明（0021）は、初期化のときだけ Batch にせず、一枚ずつその場で（同時 PHOTO_GUESS_CALL_CONCURRENCY 本）作り終えてから入り口づくりに進む（2026-11-03 追記）
  - 形: runPhotoGuesses の選択肢 noBatch と、それを渡す runMorning の選択肢 photoGuess。渡すのは初期化だけ。Cron・時計のボタン・写真の登録の後は渡さず、しきい値（10 枚）を超えたら従来どおり Batch
  - 予算 PHOTO_GUESS_DEMO_RESET_BUDGET_MS（90 秒）は、新しい写真を呼び始める締め切り。過ぎた写真と失敗した写真は次の回（翌朝・時計のボタン）に回り、入り口づくりは続ける
  - 初期化は要求の中（応答の前）で走る。HTTP の要求には時間の上限がなく（waitUntil の 30 秒の外）、外を待つ時間は CPU 時間に数えない。外へのリクエストは写真 12 枚で Claude 12〜24 本と R2・D1 数十本で、有料プランの 10,000 の内側（https://developers.cloudflare.com/workers/platform/limits/ 、2026-11-03 に確認）
  - 所要時間の見込み: 12 枚を同時 4 本で 3 巡。一枚数秒〜十数秒なので、ふだんは 20〜40 秒延びる。遅いときでも予算の 90 秒と呼び途中の分で 2 分ほど。画面の「1〜4 分」の内側
  - 実測（2026-11-03、プレビュー、写真 12 枚・語り 12 本・声 4 本、本物の Claude）: 約 2 分（人間が画面の経過で確認）。写真の説明 12 件、今日の入り口 4 人分とも Claude で作れた
- 返すのは、消した件数・入れた件数と MorningSummary（ID と件数だけ）。ログも同じ

### 画面
- /start に「デモを最初の状態に戻す」の節。家族の ID と鍵を入れて押す。鍵は画面の中だけで、送ったら消す（端末に残さない）。1〜4 分かかるので、押している間は経過の時間と進んでいる印を出す
- デモの家族そのものと人・リンクは、運営が普通の画面で一度作る（/start で「デモとして作る」→ 最初の人 → /family で残りを足しリンクを作る）

## 理由
- requirements「デモの家族（架空の三世代）の状態に、ボタン一つで戻せる」「デモ用のデータは、実際の家族と混ざらないよう別の家族として分ける」、implementation-policy 5 の 3 番目「デモの初期化が、デモの家族の外に触れないこと」
- 人とリンクを残すので、撮影のためにタブレットやスマホで開いたリンクが、初期化の後もそのまま使える
- 種を呼ばれ方で指し、一致しなければ止めるので、ID を取り違えても、別の家族の人に台本の語りを付けることがない
- 手で整えた文に model を付けると、Claude の推測の出所が嘘になる。本物の応答を一度受けて写せば、出所は正しく、初期化のたびに Claude を呼ばずに済む
- 過去の入り口に Claude の問いかけを手で書くと、Claude が言っていない言葉を Claude の言葉として残すことになる。固定の入り口なら、家族の言葉（引用）だけで言葉の糸が見える
- 最後に毎朝の処理と同じ関数を通すので、今日の入り口・写真の説明・記録・読み上げは、本番と同じ道で作られる（spec「毎朝の処理とデモ用ボタンは、同じ関数を呼ぶ」）

## 退けた案とその理由
- 初期化が家族と人・リンクまで作る: 初期化のたびにリンクが変わり、撮影の端末を開き直すことになる。家族の作り方が二つの道に分かれる
- 全部消して作り直す（家族の行ごと）: 同上。家族の ID も変わる
- 手で書いた問いかけを claude の入り口として入れる: Claude が言っていない言葉に model を付けることになる
- 手で整えた文に model を付ける: 出所が嘘になる
- 毎回、文字起こしと整形をやり直す: 初期化のたびに結果がぶれ、引用の範囲が動きうる。時間とお金もかかる
- 写真の説明を Batch のままにする: 初期化は写真を入れ直すので、毎回、説明のないまま今日の入り口ができる（プレビューで確かめた: 初期化の後 photo_guesses 0 件、作業の行 12 件が Batch 待ち）。デモで見せる入り口が本番の入り口と違う材料で作られる
- Batch のしきい値を全体で上げる: 毎朝の処理と写真の登録の後の動き（本番の家族）まで変わる。登録の後の背景処理は waitUntil の 30 秒に収まらなくなる
- 種の写真を 10 枚以下に減らす: 台本（人間が承認）を変えることになる
- 鍵を流用する（CREATE_FAMILY_TOKEN・OPS_RECORD_TOKEN で戻せる）: 鍵ごとに守るものを分ける（0027、0030）
- 家族の合言葉の cookie だけで戻せる: デモの家族のリンクを持つ人なら誰でも、撮影中に全部を戻せてしまう
- is_demo の家族を全部戻す: 試しに作ったデモの家族まで巻き込む。戻す家族は ID で明示する
- DemoBar や /ops/record にボタンを置く: DemoBar は家族の画面の中にあり、家族に見える。/ops/record は読み取りだけの画面（0025）
- 本番で 404（環境で分ける）: 本番のデモの家族（撮影・審査で使う）を戻せなくなる。守りは鍵と is_demo で足りる
- スクリプトだけ: requirements の「ボタン一つで」に届かない。画面とスクリプト（スキル）は同じ API を呼ぶ

## 追記（2026-11-05）: members.replies_seen_at は初期化で NULL に戻す（fable-advisor に相談（backend-developer））
- 返事のタブ（0058。members.replies_seen_at）を足したので、初期化の batch（消す＋入れる＋時計と同じ一つ）で、その家族の members.replies_seen_at を NULL に戻す（WHERE family_id）。「members は一行も書かない」の唯一の例外。種の返事は初期化のたびにすべて未読になる
- 理由: 前のデモで誰かがタブを開くと replies_seen_at が種の語りより新しく残り、初期化の後も未読の印が 0 になる。「ボタン一つで戻せる」「何度呼んでも同じ状態」に反する。「members を書かない」が守りたかったのは人とリンクを残すことで、時刻の状態を戻すことはその趣旨に当たらない
- 退けた案: 触らない（撮影の朝の印が履歴しだいになる）。見た時刻を別の表に持って DEMO_RESET_TABLES に入れる（人間の指定は members の列。表を増やす利益がない）
- 見直す条件: members に人ごとの状態の列がもう一つ増えたら、状態を別の表に分けて初期化の対象にする形を考える
