# 0014 実機での確かめの道具は残す。本番では画面も入り口も出さない

- 日付: 2026-11-02
- 状態: 採用
- 決めた人: fable-advisor に相談（メインの会話）

## 決めたこと

- 開発用ページ `/check`（src/client/check/）と `POST /api/check/transcribe` は残す。手元とプレビューで使う
- 本番（APP_ENV=production）では、入り口（404）に加えて `/check` の画面も出さない
- `POST /api/check/transcribe` は合言葉の確認を通す（PUBLIC_ROUTES に入れない）。人が入れた欄の値をそのまま OpenAI に送り、OpenAI が失敗しても status と本文をそのまま返す。家族のデータは読まない。写真の検査は端末の中だけで行い、外に送らない
- 開発用ページの言葉は `words.ts` に入れない。`words.ts` は家族に見せる固定の言葉の置き場（0008）で、開発用ページは家族に見せないため
- 開発用ページは家族向けの機能に育てない。家族のデータを読む必要が出たら、残すかを人間に聞く

## 理由

- 本番は家族の場。EXIF の項目や丸めた位置を表にするページは、家族が行き着けば画像解析ツールに見える（requirements「作らないもの」）。文字起こしの部分は本番で 404 なので、半分だけ動くページにもなる
- デプロイ先の HTTPS で実機から触らないと分からないことが、この道具で見つかった。ボイスメモの .m4a が `accept="audio/*"` では選べないこと（8e29d51 で直した）、`languages[]`、Android の位置、HEIC の変換。OS の更新のたびに同じ確かめが要る
- 確かめの呼び出しは差し替え層（TranscribeProbe）を通り、Workers 専用の API に頼らない

## 退けた案とその理由

- 本番でも `/check` を開けたままにする: 家族の場に、画像解析ツールの顔をした半分動かないページが置かれる
- 確かめが終わったら消す: OS の更新のたびに作り直すことになる。残す費用は小さい
- 開発用ページの言葉も `words.ts` に集める: 家族に見せる言葉の一覧に見出しやモデル名が混ざる

## 根拠にしたもの

- 実機での確かめ（2026-11-02、iPhone・iPad・Android）。結果は 0011・0012・0013・0015
- docs/requirements.md「作らないもの」「プライバシー」、docs/implementation-policy.md「4. 入力と安全（確認しない入り口の列挙）」「5. テストの考え方」、0008（固定の言葉の置き場）
