# 0052 声の語りの文字起こしを待って、一覧を静かに読み直す

- 日付: 2026-11-04
- 状態: 採用
- 決めた人: 人間（2026-11-04）

## 決めたこと
- 家族の画面・祖父母の画面（Home）で、手元の一覧（/api/feed）に文字起こしが pending の声の語りが一つでもあるときだけ、一覧を静かに読み直す。自分の声に限らない（ほかの家族の送ったばかりの声も）
- 間隔: 新しい pending の語りが現れてから 30 秒は 3 秒ごと、その後は 10 秒ごと。2 分でやめる（文字起こしに失敗して pending が残っても読み続けない）。2 分は「最後に新しい pending の語りが現れてから」数え、新しい声が届いたらまた始める
- 全部 done / failed になったらすぐやめる
- document が hidden の間は読まない。前に戻ったら続きを決める（2 分を過ぎていれば読まない）
- 画面は動かさない。声の下に文字が出るだけ。新しい言葉は足さない。「読み込み中」に戻さない。読めなかったら黙って前を残す
- 話している・書いている途中でも止めない。語りは ID で描くので、録音・書きかけの文字・開いている返事の欄・「とりなおす」は一覧の差し替えで壊れない。壊れる二つの場合だけ手当てする
  - 返事の欄を開いている語りが一覧から消えた（ほかの家族が「とりなおす」で消した）ときは、その結果を当てない
  - 段で答えている間は、一覧から「答えた」に替えない（別の端末から自分の答えが届いても段を消さない）
- アルバムの帯の並び（albumOrder）と見ている写真（albumCurrent）は動かさない
- 一覧の読み込みは一つにまとめる。待ちの読み直しは、読み込み中のもの（0051 の読み直し、送った後の読み直し）があればそれに乗る（二重に読まない）。0051 の読み直しと送った後の読み直しは常に新しく読む（裏に回る前に始まった古い読み込みや、送る前の読み込みに乗らない）。後から始めた読み込みの結果を当てた後に届いた古い結果は当てない
- サーバーは変えない。判断は src/client/lib/transcriptFollow.ts

## 理由
- 声を送った直後は声だけが出て、文字は再読み込みするまで出なかった。文字起こしは裏で数秒〜十数秒かかる
- 声の下に文字が出るのを待てば足り、知らせの言葉を増やす必要はない。0051 の「前に出ている間の定期的な読み直しはしない」は見ている写真が替わることを避けるためで、この読み直しは並びも写真も動かさず、待つものがあるときの短い間だけに限る

## 退けた案とその理由
- 「文字にしています」を出す: 知らせの言葉を増やす（アプリ自身の言葉は最小限）
- サーバーからの push（SSE / WebSocket）: 親の試しの前には大きい
- 送った語りだけを個別に読む API を足す: サーバーを変える。ほかの家族の声の文字も出したい

## 見直す条件
- 文字起こしが 2 分を超えることがよくあり、文字が出ないと家族から言われたとき
- 読み直しの通信量や電池が問題になったとき
