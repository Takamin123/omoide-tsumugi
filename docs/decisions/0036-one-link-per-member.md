# 0036 一人ずつのリンクで端末を人に結びつけ、「あなたはどなたですか」と「ほかの人にかわる」をなくす

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: 人間（一人ずつのリンクにすること、既存の家族単位のリンクをすべて使えなくしてよいこと、「あなたはどなたですか」と「ほかの人にかわる」をなくすこと、自分の画面は自分で直せないこと。2026-11-03）。データの形と入り口の形は fable-advisor に相談（backend-developer）。画面の流れと言葉は fable-advisor に相談（frontend-developer）

## 決めたこと

- 家族を作った人が、一人ずつ「その人のリンク」を作って送る。リンクを開いた端末は、最初からその人になる。「あなたはどなたですか」（端末で人を選ぶ）と「ほかの人にかわる」はなくす（画面は frontend-developer が作り直す）
- データ: `invite_links` に `member_id`（members への参照、NULL 可）を足す。新しい表は作らない
  - NULL は「最初の人のリンク」。`POST /api/families`（/start）が作る。最初の一人が自分を入れた時点で取り消す（一度きり）
  - NULL でない行は、その人のリンク。有効な行は人ごとに一つ。作り直すと、その人の前の行だけを取り消す
  - 索引: `(family_id, member_id) WHERE revoked_at IS NULL` と `(family_id) WHERE revoked_at IS NULL AND member_id IS NULL`（一意）。家族ごとに一つの索引は外す
  - 移行（drizzle/migrations/0003）で、それまでの有効なリンクをすべて取り消す
- cookie は今のまま（合言葉そのもの一つ）。cookie に人の ID を入れない。人は合言葉から引く
- 合言葉の確認は一か所のまま（`requireInvite`）。合言葉から家族と人を引く。人のいないリンクで通せる入り口は `FIRST_PERSON_ROUTES`（`GET /api/family`、`POST /api/members`）に明示的に並べ、ほかは 403 `forbidden`（cookie は消さない）
- 書き込みは cookie の人に結びつける。クライアントから人の ID を受け取らない: 語りの話者、写真の持ち主、今日の入り口の人。読み取り（feed、写真、語り、画像・録音・読み上げ）は家族の範囲のまま
- 家族のこと（人を足す・直す、リンクを作る）は、role = family の人だけができる。祖父母の画面の人の端末からは 403
- 自分の role（どちらの画面か）は自分では直せない（403）。ほかの欄は自分でも直せる。自分を祖父母の画面に変えると、その端末から家族のことを触れなくなり、戻す人がいなくなることがあるため（人間が決めた。管理者が自分の権限を外せないのと同じ）
- 直した後に role = family の人が家族に一人もいなくなる変更も 403（`changesOwnRole` と並ぶ検査）。家族の画面の人同士が同時に互いを祖父母の画面に変えると、誰もリンクを作れなくなるため。確かめと直すのは一つの UPDATE 文で行う（リポジトリの `members.update` が `"no_family_left"` を返す）。同時に送っても抜けない
- 最初の一人を入れるときは、家族に人が一人もいないときだけ受け、role は family に限る。「人を入れる → その人のリンクを作る → 最初の人のリンクを取り消す」を一つの batch で行い、新しい合言葉は cookie にだけ置く（本文には返さない）
- `POST /api/invite/regenerate` は消し、`POST /api/members/:id/link` → `{ token }` に替える。対象が自分なら cookie も替える
- これは 0010 の「合言葉は家族単位。本人は家族の場に入った後に選び、端末が覚える。サーバーは家族の中なら誰の ownerMemberId・speakerMemberId でも受ける」の段と、0008 の「`/` で『あなたはどなたですか』を選び、端末に `{ familyId, memberId }` の組で覚える」の段（と、祖父母のタブレットで話者を切り替える段）を置き換える。0028・0034 の「ほかの人にかわる」に触れた段も、画面の作り直しで外れる

### 画面（frontend-developer。2026-11-03）

- 端末の人はサーバーの `view.me` だけで決める。端末に人を覚えない（`lib/me.ts` と localStorage の `omoide.me` は消した）
- 出す画面（`lib/pure.ts` の `screenFor`）
  - me が null で家族に誰もいない（最初の人のリンク）: 「まず、あなたのことを入れてください」と、人を足す欄だけ。「画面」の欄は出さない（家族の画面に決まっている）。入れたら GET /api/family を読み直して家族の画面へ
  - me が null で家族に人がいる（同じ最初の人のリンクを二台目で開いたなど）: `noSession` の文（「家族から届いたリンクを開いてください」）
  - 祖父母の画面の人: どの道（/family、/photos を含む）でも祖父母の画面
  - 家族の画面の人: 道のとおり（/、/family、/photos）
- /start: 作った後の見出しは「最初の人に送るリンク」。URL と「コピー」、「進む」
- /family の一覧: 一人ひとりのカードの「直す」と同じ列に、補助の大きさで「リンクを作る」（hasLink が偽）／「リンクを作り直す」（真）。自分のカードにも出す。作ったら、そのカードの中に「{呼ばれ方}に送るリンク」、URL と「コピー」、補助の文「リンクは作ったときにだけ出ます」。合言葉は画面の中にだけ持ち、端末に残さない（画面を離れると消える）
  - 作り直すときだけ確かめる: 「いまのリンクは使えなくなります。いまのリンクで開いている端末は、新しいリンクで開きなおしが必要です」
  - 「直す」の入力欄が開いている間は、リンクのボタンも出さない（0032 の「ほかの人の直すを出さない」と同じ）
  - 自分のカードの「直す」では「画面」の欄を出さない（送る値は今の role のまま）
  - 家族全体の節「家族に送るリンク」と「作り直す」はなくした。「家族の番号」（0033）はそのまま
- /join/<token>: 選ばせない。開いたリンクの人になる（別の人で開いていても黙って替わる）。使えないリンク（401・400）は「このリンクは使えません。家族に知らせてください」。「{name}になりました」のような知らせは置かない
- 祖父母の画面: 上の「ほかの人にかわる」と、祖父母が二人以上のときの話者の並びを外した。呼ばれ方は上とマイクの近くに残す（0008、0028）
- 家族の画面: メニューの「ほかの人にかわる」を外した
- クライアントは人の ID を送らない（語りの送る先 `VoiceTarget`、写真の meta、今日の入り口）

## 理由

- 端末で人を選ぶと、取り違え（別の人として語る・写真を足す）が起きても、サーバーには分からない。リンクを人に結びつければ、端末を開いた時点で人が決まり、選ぶ画面も切り替えもいらない。高齢の家族の画面から操作が一つ減る
- 列を一つ足すだけで済む。リンクの表は「家族の場に入る鍵」のまま、鍵がどの人のものかを持つ。新しい表にすると、取り消しと有効の判定が二か所に分かれる
- cookie に人の ID を入れると、合言葉と人の組が食い違う場合を考える必要が出る。合言葉から引けば、食い違いが起きない
- 書き込みの人をクライアントから受け取らなければ、ID の不一致を弾く検査も要らない
- 「ほかの人にかわる」をなくすのは、高齢の人が意図せずボタンを押して、見知らぬ画面に行って混乱するのを避けるため（人間）
- リンクのボタンを一人ひとりのカードに置くと、誰のリンクを作っているのかが文字で分かる。家族全体の節に人を選ぶ欄を作ると、選び間違いの道が増える
- 「リンクは作ったときにだけ出ます」を作ったリンクのそばに出すのは、いまコピーしないと後で見られないことを、要るときにだけ伝えるため（作る前のカードすべてに出すと読む量が増える）
- 最初の人のリンクを一度きりにすれば、/start で渡したリンクが後で誰かに開かれても、家族の場に入れない

## 退けた案とその理由

- 新しい表（member_links）: 合言葉の確認が二つの表を見ることになり、取り消しの規則が二か所に分かれる
- cookie に memberId を入れる: 合言葉と人の組の食い違いを考える必要が出る。合言葉だけで人が引ける
- /start で最初の人まで入れる: 運営が家族の呼ばれ方などを入れることになる。始める人が自分で入れる方が、家族の言葉で始まる
- クライアントから人の ID を受け取り、cookie の人と違えば弾く: 送る値が増えるだけで、守れるものは同じ。受け取らない方が単純
- 移行の画面（古いリンクの端末に「新しいリンクを開いてください」を出す）: 家族単位のリンクで使っている家族は数えずに作り直してよい（人間の決定）。401 の「リンクを開きなおしてください」で足りる
- /join で「この端末を○○さんにかえますか」と確かめる: 一人ずつのリンクは送った相手が開く。確かめる一手が高齢の家族の負担になる
- デモ用の、人を切り替える API: デモの端末もリンクで人に結びつける。切り替えがあると「ほかの人にかわる」が裏口として残る
- 自分のカードの「直す」で「画面」の欄を押せなくして見せる: 押せない欄は、なぜ押せないのかの説明が要る。出さない方が言葉を足さずに済む
- 家族の画面の人がいなくなる変更を、画面だけで止める: 同時に二台から直すと抜ける。サーバーの一つの文で止める
- リンクを作ったら「{呼ばれ方}になりました」のような知らせを /join で出す: アプリ自身の言葉を増やす。開いた画面に呼ばれ方が出ていれば足りる
- 家族を作った人だけが家族のことを触れる: 作った人の端末が無くなると、誰も人を足せなくなる。role = family の人なら誰でもよい

## 見直す条件

- 取り違え（別の人のリンクを開いてしまった）が起きたら、/join に「○○さんのリンクです」の一文を足すことを考える
- 家族の画面の人が一人の家族で、その人の端末が無くなったら、誰もリンクを作れない。そのときは、運営がリンクを作る script を用意するかを人間に聞く
- デモの初期化を作るときは、人とリンクを残す（初期化のたびにリンクが変わると、撮影の端末を開き直すことになる）
- 共用の端末で、話す人を分けたいと言われたら（0037 を見直す）
