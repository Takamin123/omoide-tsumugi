# 0012 写真の位置は「あれば使う手がかり」。ないことを家族に知らせず、場所は語りで持つ

- 日付: 2026-11-02
- 状態: 採用（「位置から地名を引かない」は [0047](0047-photo-date-place.md) で置き換え済み。ほかはそのまま）
- 決めた人: fable-advisor に相談（メインの会話）

## 決めたこと

- 写真の位置は、EXIF にあれば丸めて取り込む（0010）。なければ null のまま登録する。requirements の「撮影日と位置情報を取り込む」は「写真にあれば取り込む」と読む
- 位置がないことを家族に知らせない。端末の設定の案内を出さない。位置を入れる欄を作らない
- 場所は家族の語り（records の kind=place、origin=told）で持つ。位置は「同じ場所の写真をまとめる」裏方の手がかりにだけ使う
- 位置から地名を引かない（逆ジオコーディングをしない）。地名は家族の言葉から

## 理由

- 写真を求めず、思い出を聞く。位置がないと伝えることは、写真や設定の手直しを求めること
- Android の Chrome は、選ぶ部品の指定によらず位置だけを消して渡す（OS の仕組み）。家族にできることがない
- 推測は問いかけの形でしか使わない。場所は家族の言葉で埋まるのが筋で、位置がないことは開かれた問いかけの理由の一つになるだけ
- 位置から引いた地名を見せると、画像解析ツールの顔つきになる。つなぐサービスも増える
- 家族が場所を足したければ、文字の語りで返せばよい。それは出所つきの家族の言葉

## 退けた案とその理由

- 登録の画面で「位置なし」を知らせる: 手直しを求める形になり、Android では直せない
- iOS の「オプション」の操作を案内する: 端末ごとの説明がアプリに入り、合わない端末が必ず出る
- 位置を家族が入力する欄や地図: 語りと別の入力の道ができる
- 位置から地名を引く: 機械の言葉が家族に見える。サービスが増える

## 根拠にしたもの

- 実機での確かめ（2026-11-02、開発用ページ `/check`、0014）
  - iPhone・iPad の Safari: 撮影日・位置・EXIF が残る。写真を選ぶ画面の「オプション」で位置情報を外すと、位置は「なし」。`accept=image/*` と `accept` なしで同じ結果。カメラのフォーマットが「高効率」（HEIC）でも、選んだ時点で JPEG に変えて渡される
  - Android の Chrome: `accept=image/*` でも `accept` なしでも、撮影日と EXIF は残り、位置だけ「なし」。同じ写真を Google フォトで開くと地図が出る（写真には位置が入っている）。Android 10 以降の、位置を読む許可（ACCESS_MEDIA_LOCATION）のないアプリには位置を伏せる仕組みによるとみられる
- docs/requirements.md「AI のふるまい」「記録と言葉」「作らないもの」、0010（位置の丸め、クライアントには有無だけ）

## 見直す条件

- むすびで、位置がないとまとめられない場面が多いと分かったとき。まず家族の言葉でまとめられないかを考え、座標を家族に求める側には倒さない
- ブラウザが許可つきで位置を渡す仕組みを持ったとき
- 家族が「場所を書き足したい」と言ったとき（文字の語りで足りるかを先に見る）
