# 0044 むすびの推測（musubi_guess）

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: fable-advisor に相談（backend-developer。モデルと person の扱いは qa-engineer 経由の相談を含む）。作ること・用途と Sonnet（出し比べで差がなければ Haiku）・根拠の記録の ID を必ず付けること・確定は家族の手だけ・入り口への答えで確定にしないことは人間が承認

## 決めたこと

### 範囲
- むすびは 0010 の定義（同じ出来事）のまま。種類の列（同じ場所・同じ人・語りの連想）は作らない
- 語りが別の写真の出来事を指すつながり（台本の n8「最上川の岩を見て、伊勢で夫婦岩を見たときを思い出した」→ P4）は作らない。別の結びつきとして持つかは人間に聞く（下の「人間に聞くこと」）
- 家族への見せ方と入り口での使い方（entrance v3）は今回やらない。家族向けの API にも運営の記録の画面にも出さない（家族向けの API に出ないことはテストで固定）

### いつ、何を渡すか
- 毎朝の処理（runMorning）の家族ごとのループで、runRecordExtraction の後・入り口づくりの前に `runMusubiGuess(deps, familyId)` を呼ぶ。投げない。Cron・デモの時計のボタン・デモの初期化は同じ関数を通る（0009、0038）
- 家族ごとに一回の呼び出し（Sonnet、用途 musubi_guess）。渡すもの:
  - told の記録（写真と語りのあるもの。新しい順に 150 件まで、その語りの本文の合計 20,000 字まで。定数）
  - その語りの表示の文字（displayText。印は「……」）と語り手の呼ばれ方。記録の値だけだと、別の出来事を思い出して触れた語の形の一致（n1 と n8 の「夫婦岩」）が検査を通るので、本文を文脈として渡す
  - 記録のある写真の一覧（持ち主の呼ばれ方、撮影日時。撮影日時は手がかりで、根拠には数えない）
  - すでにあるむすび（guessed / confirmed）の写真の組
- 渡さないもの: 写真の説明（photo_guesses。推測の上に推測を重ねない）、画像、位置、本当の ID。写真・語り・記録は短い呼び名（p1、n1、r1）で渡し、アプリが本当の ID に戻す
- 記録のある写真が 2 枚未満の家族は呼ばない

### 返させるものと検査（応答全体の全か無か。違反は 1 回だけ再試行）
- 構造化出力 `{ musubi: [{ photo_ids, evidence_record_ids, reason }] }`。空の配列を許す。家族に見せる文（むすびの名前など）は作らせない。見せるときは根拠の記録の値（家族の言葉）を見せる
- 検査: 写真と記録の呼び名は渡したものだけ（＝その家族の told の記録と、その記録のある写真）。写真は 2 枚以上で重複なし。根拠の記録は 1 件以上で、どれもむすびの写真の記録。むすびのどの写真にも根拠の記録がある（両側に家族の言葉がある結びだけ）。応答の中で一枚の写真は一つのむすびだけ。理由は空でなく 100 字以内。むすびは 20 個まで
- 重複除け（違反ではなく、そのむすびだけ捨てる。数をログに出す）: 既存の guessed / confirmed のむすびと写真が一枚でも重なるもの、家族が却下した組（むすび M で却下された写真と M のほかの写真）を含むもの。既存のむすびに写真を足すことは今回しない

### 保存
- musubi: created_by = 'guessed'、model、prompt_version、guessed_evidence_record_ids（JSON の配列。guessed なら必須の CHECK）、guessed_reason（Claude の自由文、運営と開発だけが見る）
- musubi_photos: status = 'guessed'。確定・却下は家族の手だけ: decided_by_member_id を足し、CHECK を「guessed なら決めた人と時刻なし、confirmed / rejected なら決めた人と時刻が必須」に変える。evidence_narration_id は語りを通して決めたときの任意の印に下げる
- 作業の表 musubi_guess_runs（PK family_id + input_key、input_key は渡した told の記録 ID の集合の SHA-256。prompt_version、model、state done|failed、attempts、トークン、created_at）。同じ記録の集合で done があれば呼ばない。版は鍵に入れない（版が上がっただけでは呼び直さない。0039 と同じ）。新しい記録が入った朝に呼び直す
- むすびと作業の行の done は一つの batch で、同じ鍵の done がまだないときだけ入れる（同じ朝の処理が重なっても一組）。写真はその家族のものだけが入る
- failed は attempts が 3 回に届くまで翌朝に取り直す。キーがない、時間の予算（60 秒。呼ぶ前に過ぎていたら呼ばない）、記録のある写真が 2 枚未満は行を残さない
- マイグレーション 0005_musubi_guess。CHECK を変えるので musubi と musubi_photos を作り直す。D1 では外部キーを切れないので、musubi_photos を外部キーのない一時の表に写してから消し、musubi を作り直し、musubi_photos を作り直して戻す。前の形の推測（根拠の記録がない）は写さない。前の形の確定・却下は、根拠の語りの語り手を決めた人にする（どの環境にも行はないはず）
- 家族の削除（scripts/delete-family.mjs）とデモの初期化（DEMO_RESET_TABLES）の表に musubi_guess_runs を足す

### モデル
- Sonnet（claude-sonnet-5-5）のまま。人間の判断は「Sonnet、出し比べで差がなければ Haiku」。直した後の出し比べでは差が小さく、3 回では「差がない」と言い切れず、むすびを使う側（問いかけの材料）がまだないので、コードは Sonnet のままにして人間に返す（下の「人間に聞くこと」）
- 根拠に人の記録（person）を数えない。プロンプト v1 の「まとめ方」に書き（v1 は本番で使う前に足した。0039 と同じ）、検査では person を外した後に、むすびのどの写真にも根拠が残ることを求める。保存する根拠からも外す。person が混じっただけで応答全体を違反にはしない（再試行が増える）
- P5・P8 を拾うためにプロンプトを緩めない。取りこぼしは新しい記録が入った朝に拾い直せるが、間違ったむすびは家族に却下の手間を生み、却下した組は以後除外される（「迷ったら、まとめない」）。P8（「二日目の朝、大きな木の前で」）は撮影時刻が主な根拠になるので、拾わないのが正しい。デモで旅全体を一つにしたいなら、直すのは台本（家族の言葉。声は人間が読んでいるので人間が決める）

### ログ
- ID・件数（渡した記録、作った・捨てたむすび）・状態・所要時間・トークン・違反の種類・入力の鍵の先頭だけ。語りの本文、記録の値、理由は出さない

## 理由
- 家族が語ったことと Claude の推測を分ける（requirements、0010）。n8 → P4 は家族が語ったつながりなので、guessed のむすびにすると出所が逆になり、同じ出来事として束ねれば作り話になる
- 根拠が両側の写真の記録に戻れる結びだけを残すのは、後で問いかけに使うとき引用元があるため（「推測は問いかけの形でしか使わない」）。撮影日だけの束ねは Claude の推測だけで立つ
- 0010 の定義は人間が決めたもので、広げる判断はここでしない
- 壊れた応答の一部を拾わない（implementation-policy 2）。根拠を一つでも作った応答は、残りも地に足がついていない疑いがある。重複は Claude の落ち度ではないので再試行に回さない
- 短い呼び名は、本当の ID の書き写し違いと、ほかの家族の ID の混入を構造で止める（呼び名の表に無いものは違反）
- 朝の処理に置くので、Cron とボタンとデモの初期化が同じ経路になる。記録の取り出しの後なので、前日の語りの記録が材料に入る

## 退けた案とその理由
- P5・P8 を拾うようにプロンプトを緩める（「二日目」「家族旅行」と撮影日時を合わせて同じ旅としてよい、など）: 撮影日時が主な根拠になる組を招き、Y1–Y2 のような罠に近づく
- Haiku で拾って Sonnet で確かめる併用: 呼び出しが二回になり、今の規模で要らない
- person の根拠が混じったら応答全体を違反にする: 再試行が増える。外してから各写真に根拠が残るかを見れば足りる
- 種類の列（told_link / same_place / same_person）: 定義の変更（人間）。同じ人は家族の写真のほとんどがつながる。同じ場所・同じ人は 0010 が records の側に置いた
- 根拠 1 件以上だけ（片側の写真に言葉がなくてよい）: 撮影日だけで束ねられる
- 写真の説明を渡す: 推測の上に推測。根拠に残らない
- むすびごとの全か無か: 根拠を作った応答の残りを信じることになる
- 作業の表なしで records.created_at を見る: 失敗の回数が数えられない
- 版を作業の表の鍵に入れる: 版が上がるたびに全家族で呼び直し、大半が重複除けで捨てられる呼び出しに費用を払う
- 既存のむすびへ写真を足す: 今回の範囲外。重なりで捨てた数を見てから
- CHECK に「OR evidence_narration_id IS NOT NULL」を残す: 「確定は家族の手だけ」を一つの条件で言えなくなる

## 人間に聞くこと
- 「最上川の岩を見て伊勢の夫婦岩を思い出した」のように、語りが別の写真の出来事を指すつながりを、0010 の「同じ出来事」のむすびとは別の「家族が語った結びつき」として持つべきか（持つなら、むすびの種類ではなく別の名前の結びつきにする）
- むすびの推測は、直した後の出し比べで Sonnet と Haiku の組と根拠がほぼ同じだった（Sonnet は最小の組に留まる回が多く、Haiku は出力トークンが約 1.7 倍。費用は一家族一朝一回で小さい）。Haiku に倒すか、問いかけに使う形ができるまで Sonnet のままにするか

## 見直す条件
- 人間が「語りが別の写真を指すつながり」を持つと答えたとき（別の結びつきとして設計する）
- 出し比べや本番で、旅が場面に割れる・別の出来事が一つになる、P4–Y2 や Y1–Y2 のような連想・同じ日だけのむすびが出るとき
- 重なりで捨てた数が続くとき（既存のむすびへの写真の追加を設計する）
- told の記録が 150 件・本文 20,000 字を超える家族が出たとき（渡す範囲の切り方を見直す）
- 毎朝の処理で、家族ごとに写真の説明（最大 60 秒）・記録の取り出し（最大 60 秒）・むすびの推測（一回、最長で 2 分ほど）が入り口づくりの前に走るので、入り口の予算（7 分）の past_deadline が出たとき
- デモの初期化が 4 分に近づいたとき（0038）
- 人間が「Haiku」と答えたとき（倒して claude.ts のコメントとこの記録を直す）。むすびを問いかけの材料に使う実装が入ったとき（その形で回数を増やして出し比べる）
- 理由の文が撮影日時を主な根拠にし始めたとき（撮影日時は手がかりで、根拠に数えない）

## 人間の決定（2026-11-04。fable-advisor の区切りの全体レビュー 2026-11-03 の推しのまま）

上の「人間に聞くこと」への答え。

- むすびの推測のモデルは、入り口 v3（むすびを問いかけの材料に使う形）ができるまで Sonnet のまま。Haiku に倒すかは、v3 の形で出し比べてから決める
- 語りが別の写真の出来事を指すつながり（台本の n8 → P4）は、親の試しの後まで持たない。持つなら、むすびの種類ではなく別の名前の結びつきとして設計する（「見直す条件」の 1 つ目のまま）

## 前段の予算（2026-11-04 追記。fable-advisor に相談（backend-developer））

- 毎朝の処理の前段の三つ（写真の説明・記録の取り出し・このむすびの推測）は、処理全体の締め切り `MORNING_PRELUDE_BUDGET_MS`（処理の始まりから 5 分。入り口の予算 7 分から、Claude の入り口一人分の最長 2 分を残す）の残りで、各自の予算を切り詰めて受け取る。残りが 0 なら呼ばない（翌朝に回る。`morning_done` の `preludeSkipped` に数える）
- fable-advisor の指摘（2026-11-03）は「前段に、入り口の締め切り（7 分）までの残りを渡す」だった。それだと前段が 7 分を使い切った朝に、後ろの家族の入り口が固定に倒れる。前段は家族に見えず翌朝に回せ、入り口は家族が今日見るので、入り口の分を残して前段を止める形にした
- fable-advisor の確認（2026-11-04）: 余白 2 分は Claude の入り口一人分の最長（60 秒 × 2 と待ち）と同じ単位。余白 1 分は一人分の最長を下回るので退けた。余白が保証するのは「前段のせいで入り口が始めから固定に倒れないこと」（前段が止まった後に、少なくとも一人分は Claude で試せること）で、残りの人が全員 Claude で作られることではない。締め切りの直前に始めた前段の一回の呼び出しが最長（2 分ほど）まで延びた朝は、余白が尽きうる（code-reviewer の指摘。ふだんの一回は数秒〜十数秒なので、そのままにした）（残りが多ければ、後ろの人は入り口の締め切りで固定に倒れる。これは正しい動き）
- 見直す条件: 本番の家族が複数になり、preludeSkipped が続く朝が出たとき（前段の取り分か、前段を入り口の後ろに回す順番を考える）。Claude の入り口一人分の最長（60 秒 × 2）を変えたとき（余白を連動させる）。上の「見直す条件」の「入り口の予算の past_deadline が出たとき」も残す
- テスト: test/morning-budget.test.ts（家族 3 つで前段が遅いとき、後ろの家族の入り口が予算の内側で作られる）
