# 0017 入り口づくり（Sonnet）のプロンプトの方針

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: fable-advisor に相談（メインの会話）。費用、理由を見せる相手、photo_guesses を使うことは人間

## 決めたこと

### 渡す材料
- 候補の写真は、ルールで先に **6 枚まで** に絞る（定数 `MAX_ENTRANCE_CANDIDATES`）。並べる順:
  1. ほかの家族が語った写真で、その語りの後にこの人の入り口に出していないもの
  2. ほかの家族の写真で、まだ出していないもの
  3. 自分の写真で、まだ出していないもの
  4. 最後に出したのがいちばん古いもの
- 前の 7 日に出した写真は、1 以外では候補にしない（定数）。同じ写真を続けて出さないことは、プロンプトではなく候補の絞り込みで止める
- **画像そのもの**（R2 にある縮小済みのもの）と、photo_guesses の説明があればそれも渡す（説明は推測として扱う）
- 写真ごとに渡すもの: photo_id、持ち主の呼ばれ方、撮影日（年月日まで）、この人に出した回数と最後の日付、語り。語りは、語り手の呼ばれ方、narration_id、表示用の文字（cleaned_text の聞き間違いの印の部分を「……」に置き換えたもの）。未整形の語りは transcript を「文脈だけで、引用はできない」として渡す
- 家族の一覧（member_id、呼ばれ方、続柄、role）と、受け取る人の member_id も渡す
- 渡さないもの: 緯度経度（あるかどうかも渡さない）、storageKey と URL、合言葉。語りは新しいものから 20,000 字まで

### 写真の選び方（プロンプトに書く優先順位）
- 相手の言葉が届く向きに選ぶ。祖父母（elder）には家族（子・孫）の写真と言葉を、家族（family）には祖父母が語った写真を優先する
- 家族の言葉が付いている写真 → ほかの家族の未提示の写真 → 自分の写真で、まだ語られていないもの

### focus（写真のどこから見せるか）
- 「最初に見せる範囲」。画像に対する比率 0〜1 の `{x,y,w,h}`。null も許す
- 機械的に検査する: 0 ≤ x, y、x+w ≤ 1、y+h ≤ 1、w と h は 0.25 以上（顔を切り抜くような小さな枠を出させない）
- 画面では中心点に寄せるだけ。拡大してから引くような動きは、磨き込みのときに決める

### 問いかけ
- 入り口を受け取る人に向けて、その人の思い出を聞く。語り手の呼ばれ方は使ってよい
- **今日は、問いかけに Claude の推測を入れない。** 写っている人・場所・出来事を言い当てず、「この日」「この写真のころ」のように指すだけにする。材料にするのは、家族が語ったこと（出所つき）だけ。推測は reason にだけ書く
- 標準的な丁寧語にする。家族の方言をまねない
- 機械的に検査する: 60 字以内。文は一つ。末尾は「か」「か？」「ください」のどれか。禁止語（定数の一覧、部分一致）: 覚えて、ご記憶、思い出せ、分かりますか、わかりますか、知っていますか、誰ですか、どこですか、いつですか、何年、正しい、当て、クイズ、写真を、送って、見せて、撮って、AI、私、分析、！、絵文字、冒頭の相づち（わあ、素敵、いいですね、なるほど）
- 違反したら 1 回だけ再試行し、だめなら固定の入り口にする

### 添える家族の言葉（引用）
- Claude には narration_id と**引用する文字列そのもの**を返させる。アプリが表示用の文字（cleaned_text、文字の語りなら transcript）の中から位置を探し、start/end を決める。見つからなければ違反
- 引用できるのは、文字の語りと、cleaned_text のある声の語りだけ
- 聞き間違いの印（uncertain_spans）と重なったら違反
- 80 字以内（定数）。受け取る人以外の語りを優先する

### reason
- 200 字以内。どの候補を選び、なぜほかより上か、focus をそこにした理由、材料にした語りの ID を書く。推測を書いてよい
- **見るのは運営と開発だけ。** 家族の画面には出さない。記録の画面は、合言葉とは別の鍵で守る

## 理由
- requirements の「入り口は 4 つでできている」「家族が語ったことと推測を分ける」「写真を求めない」「試す問いかけをしない」。implementation-policy の「構造化出力」「機械的な検査」「全か無か」「渡すのは要るものだけ」
- focus を決めるには、画像を見せる必要がある
- 文字数は LLM が数えると外れやすい。外れると、言っていない切れ方で引用が出る（0011 と同じ理由）
- 理由を家族に見せると、「家族に見せる言葉は家族の言葉を中心にする」に反する

## 退けた案とその理由
- 全部の写真を渡して Claude に選ばせる: 費用と時間が枚数に比例して伸びる。「同じ写真を続けない」をプロンプトに頼ることになる
- 画像を渡さず、説明だけを渡す: focus が出せない
- 問いかけに推測を入れる（「海のそばでしょうか」）: 言い当てる形は、試す問いかけや画像解析に見えやすい。今日はまだ出し比べもできていない
- start/end を Claude に数えさせる: 外れやすい
- 祖父母の方言で問う: Claude の言葉が家族の言葉に見えてしまう
- reason を家族にも見せる: 人間が退けた

## 根拠にしたもの
- fable-advisor との相談（2026-11-03）
- 人間の判断（2026-11-03）: 画像は 6 枚まで渡す（家族 5 人で一日 0.3 ドル前後の見積もり）。理由を見るのは運営と開発だけ。photo_guesses も今日作る（fable-advisor は「今日は使わない」を推したが、写真の初回整理は今日作るものとして指示された）
- docs/requirements.md、docs/implementation-policy.md、0009、0011、0012

## 見直す条件
- 写真が 50 枚を超えて、候補の絞り込みが雑になったとき → photo_guesses で先に絞り、画像を渡す枚数を減らす
- 出し比べで、問いかけが平板で同じ型ばかりだと分かったとき → 推測を問いかけの形で使う範囲を決める
- 毎朝の処理が 10 分に近づいたとき
- 家族が「なぜこの写真か」を知りたいと言ったとき → 人間が決める
