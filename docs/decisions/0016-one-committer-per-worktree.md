# 0016 同じ作業ツリーでコミットする実装エージェントは一人。「通った」には出力を付ける

- 日付: 2026-11-02
- 状態: 採用
- 決めた人: 人間（fable-advisor の区切りのレビューの指摘を受けて）

## 決めたこと

- 同じ作業ツリーでコミットする実装エージェントは、一度に一人だけ。並行して作業させるときは `git worktree` で作業ツリーを分ける
- ステージは触ったファイルをパスで明示する。`git add -A`・`git add .` は使わない。コミットの前に `git diff --cached --stat` を自分の触ったファイルの一覧と突き合わせる。code-reviewer もファイルの一覧が頼まれた変更と合っているかを見る
- 型の検査の入口は `npm run typecheck` 一つにする（test/ も Workers の型で検査される）。実装エージェントは「通った」と報告するとき、`npm run typecheck` と `npm test` の出力の末尾を貼る
- qa-engineer は、実装エージェントの報告を信用せず、自分で `npm run typecheck` と `npm test` を走らせる
- `.envrc`（個人の direnv の設定）は `.gitignore` に入れ、`git status` を空に保つ
- 各エージェントの定義ファイル（.claude/agents/）に書く（0001: 進め方は各エージェントの定義に書く）

## 理由

- 2026-11-02 に backend-developer と frontend-developer を同じ作業ツリーで並行させたところ、ステージを共有していたため、一方のコミットにもう一方のファイルが混ざった（すぐ取り消してコミットし直した）
- 同じ日、frontend-developer が「型の検査は通っている」と報告したが、`npm run typecheck` では test/client/check-gate.test.ts が落ちていた（470e51e で直した）。部分的な検査では、test/ の型のずれは見えない
- 未追跡のファイルが `git status` に残っていると、巻き込みのコミットが起きやすい

## 退けた案とその理由

- 並行させずに常に一人ずつ: 独立した作業（サーバーと画面）の待ち時間が増える。worktree で分ければ並行できる
- 報告の言葉を信じ、メインの会話だけで確かめる: 確かめる人が一人になり、見落としがそのまま積まれる。テストの担当が自分で走らせれば、確かめが二重になる
