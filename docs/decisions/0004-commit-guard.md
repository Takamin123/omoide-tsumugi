# 0004 写真・録音・データベース・秘密の値をフックで止める

- 日付: 2026-11-02
- 状態: 採用
- 決めた人: 人間

## 決めたこと

- コミットの前に、写真・録音・SQLite のデータベースファイル・.env・.dev.vars・API キーらしき文字列を機械的に検査し、見つかったら止める
- 止める仕組みは二つ置き、どちらも同じスクリプト `scripts/check-staged.sh` を使う
  - git の pre-commit フック（`.githooks/`）。人間のコミットも止める。`git config core.hooksPath .githooks` で有効にする
  - Claude Code の PreToolUse フック（`.claude/settings.json`）。エージェントの `git commit` を止める。`--no-verify` で git のフックを飛ばすことも止める。また、git のフックが有効になっていない環境でも止まる
- デモ用の架空の写真と録音も、リポジトリに入れない。R2 の demo/ に置く。リポジトリに入れてよい画像は SVG だけにする

## 理由

- 一度コミットした写真や声は、履歴から完全には消しにくい。実際の家族のデータなので、取り返しがつかない
- エージェントの判断に任せると、見落とすことがある。確実に止めるには、機械的な検査が必要
- 「デモ用なら入れてよい」という例外のフォルダを作ると、そこに本物の写真を置いてしまったときに止められない

## 退けた案とその理由

- git のフックだけ: `core.hooksPath` は clone しただけでは有効にならない。また、`--no-verify` で飛ばせる
- Claude Code のフックだけ: 人間のコミットを止められない
- demo/assets/ だけを例外にする: 上に書いた理由で退けた（人間が選んだ）

## 見直す条件

- 正当なファイルが繰り返し止められて、作業が進まないとき。そのときは例外を足さずに、置き場所を変えられないかを先に考える
