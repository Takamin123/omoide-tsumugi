# 0007 実装の方針の資料を置き、迷ったときの倒し方を決める

- 日付: 2026-11-02
- 状態: 採用
- 決めた人: 人間（資料を置くこと、入れる観点）、fable-advisor に相談（メインの会話。各観点の倒し方と数値、追加の観点）

## 決めたこと

- docs/ に [実装の方針](../implementation-policy.md) を一つ置く。細かい規約ではなく、迷ったときにどちらに倒すかだけを書く。ソースを読めば分かることは書かない
- 主な倒し方
  - 入り口が作れなかった日は、Claude なしの「固定の入り口」を出す。家族の言葉は、引用がなければ空にする。失敗を家族に知らせない。一度見せた入り口は差し替えない
  - 毎朝の処理は、失敗した人だけ飛ばして続ける。家族一人 × 日付で入り口は一つ（冪等）
  - Claude は構造化出力で受け、受け取った後に中身を検査する。時間切れは 60 秒、再試行は 1 回。家族の言葉は語りの ID で受け、本文はアプリが引く
  - ログには ID、件数、所要時間、モデル名、版、トークン数だけを出す。プロンプトの全文は、本番とプレビューで保存しない
  - 固定の言葉はクライアントの一か所に集める。Claude の言葉はデータとして出所つきで保存する
  - Claude と文字起こしも差し替えられる層に入れ、`npm test` は偽物で動かす
  - 合言葉の確認は一か所で、既定で閉じる
  - 高齢の人の画面: 文字 20px 以上（補助 16px 以上）、コントラスト 4.5:1、押せる場所 48px 以上、主な動作は 64px 以上
- fable-advisor が足した観点: 冪等、時刻は日本時間、Claude に渡すものを最小にする、つなぐサービスを増やさない

## 理由

- 失敗した日を Claude の言葉で埋めると、「作り話をしない」「Claude の言葉は最小限」に反する。固定の入り口は Claude の言葉がない、いちばん安全な側
- 一人の失敗で全員に届かなくなるのは、「毎朝、一人ひとりに届く」に反する
- 家族の言葉の本文を Claude に書かせると、言い換えが作り話になる道が残る。ID で受ければ、作りの上で防げる
- Workers のログは Cloudflare 側に残るので、語りの本文を出すと外に出る道になる。版と入力の ID があれば組み直せるので、調べる力は落ちない
- 合言葉の確認を入り口ごとに書くと、入り口を足したときに抜ける
- テストで本物を呼ぶと、費用と再現性が悪くなる。また、実際の語りが評価に混ざる道ができる
- 画面の数値は、WCAG AA と押せる場所の一般的な下限（44〜48px）を、高齢の人向けに少し上に倒した

## 退けた案とその理由

- 失敗した日は前日の入り口を出す: 答え済みの問いかけがもう一度出る。前日も失敗なら連鎖する
- 失敗した日は、汎用の問いかけを Haiku で作る: 原因が Claude 側なら同じく失敗する。失敗したときにこそ Claude の言葉を増やすのは、方針の逆
- 失敗を家族に知らせる: AI の仕組みを前に出す。家族の体験に要らない
- 一人の失敗で処理全体を失敗にする: 届く人まで届かなくなる
- プロンプトと応答の全文をログに残す: 語りが外に残る
- 壊れた応答の一部を拾って使う: 壊れたものが画面に出る道になる
- テストで本物の Claude を呼ぶ（記録して再生する形を含む）: 費用、速度、実際のデータが混ざる道
- 入り口ごとに合言葉の確認を書く: 新しい入り口で抜ける
- 資料に入れなかったもの:
  - コーディング規約: ツールの設定が正
  - 監視とアラート: 1週間では `wrangler tail` で足りる
  - 国際化: 日本語だけ
  - 画面の自動アクセシビリティ検査: 手間が利点を上回る
  - 合言葉の試行回数の制限: 合言葉の形を決めるときに考える
  - バックアップ: D1 の Time Travel がある
  - 性能の目標: 測ってから決める

## 根拠にしたもの

- docs/requirements.md「守る方針」、0002（逃げ道）、0004（データをリポジトリに入れない）
- WCAG 2.x のコントラスト比 4.5:1（AA）
- Cron Triggers の実行時間の上限: https://developers.cloudflare.com/workers/platform/limits/

## 見直す条件

- 家族が増えて（目安は20家族を超えたとき）、毎朝の処理が 10 分を超えたとき → 並行数を変えるか、処理を分ける
- 固定の入り口が週に何度も出るとき → 時間切れと再試行を見直す。または、障害として人間に知らせる
- 高齢の家族に使ってもらって、文字や押せる場所が小さいと分かったとき → 数値を上げる（下げない）
- 調べるために、本番のプロンプトの全文が必要になったとき → 人間が決める（実際の家族の語りを含むため）
- Opus を使いたくなったとき → 人間が決める（費用）
- VPS に切り替えたとき → Cron の 15 分の制約はなくなるが、冪等と「一人ずつ飛ばす」は保つ
