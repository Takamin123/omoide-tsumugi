# 0058 「返事」のタブ

- 日付: 2026-11-05
- 状態: 採用
- 決めた人: 人間（2026-11-05。タブに出すもの、祖父母の画面にも付ける、見たはタブを開いたとき・人ごとにサーバー）。デモの初期化での扱いは fable-advisor に相談（backend-developer）

## 決めたこと
- 「今日」「アルバム」の隣に 3 つ目のタブ「返事」を足す。家族の画面と祖父母の画面の両方。バッジにまだ見ていない数を出す
- タブに出すのは、その人について:
  - (a) その人の語りに、ほかの家族がした返事（narrations.reply_to_id がその人の語り）
  - (b) その人が入れた写真（photos.owner_member_id がその人）に、ほかの家族が残した語り（返事でないものも、返事も）
  - (a)(b) の重なりは一つに数える。自分の語りは数えない。声の語りは文字起こしの状態（pending・failed）に関わらず数える。返事の返事は (a) の一段だけを見る
- 「見た」はタブを開いたときにまとめて付ける。人ごとにサーバーに覚える（別の端末でも数が合う）

### サーバー側（backend-developer）
- members.replies_seen_at（integer、UTC のミリ秒、null 可）。null はまだ一度も開いていない（すべて未読）。既存の行は null
- GET /api/feed の応答に repliesSeenAt（この端末の人の値）を足す。型は src/shared/api.ts の FeedResult
- POST /api/replies/seen → 204（本文なし）。サーバーの今の時刻を入れる。クライアントの時刻は受け取らない（端末の時計のずれで数が狂わないように）。認証・家族の絞り込みはほかの入り口と同じで、触れるのはこの端末の人の行だけ
- 一覧と未読の数はサーバーで数えない。クライアントが feed と repliesSeenAt から、src/shared/replies.ts の repliesFor(feed, meId)・unseenReplies(items, seenAt) で作る。未読は createdAt > repliesSeenAt（ちょうど同じ時刻は見たことにする）。feed はもとから家族の語りをすべて持つので、増える読み込みはない
- デモの初期化（0038）は、その家族の members.replies_seen_at を NULL に戻す（同じ batch の中、WHERE family_id）。0038 に追記

## 理由
- requirements「入り口を開いた後は、家族同士が直接やり取りする」。自分の語りや自分の写真に家族が言葉を返したことに気づけないと、やり取りが一往復で止まる
- 数え方を一か所（src/shared/replies.ts）に置き、家族の画面と祖父母の画面で同じ決まりを使う。サーバーで数えないので、feed と数が食い違わない
- 0042 の g0（自分の語りへの返事がある写真を翌日の入り口の候補の先頭に置く）は、Claude の入り口で返事を運ぶ道。返事のタブは家族が自分で見に行く道で、g0 とは独立に動く（タブで見ても g0 は外れない。g0 は「その人の入り口に出したか」で決まる）

## 退けた案とその理由
- 見た時刻を端末に持つ: 別の端末（祖父母のタブレットと、手伝う人のスマホ）で数が合わない
- サーバーで未読の数を返す: 決まりが二か所になる。feed にすでに材料がある
- 語り一つずつに既読を付ける: 人間の決定は「タブを開いたときにまとめて」。表が増える
- デモの初期化で replies_seen_at に触れない: 前のデモでタブを開くと、初期化の後も印が 0 になり、「ボタン一つで同じ状態に戻せる」に反する
- 見た時刻を別の表に持って初期化の対象にする: 人間の指定は members の列。今は一列なので分ける利益がない

## 根拠にしたもの
- docs/requirements.md、0035（アルバムの糸）、0038（デモの初期化）、0042（g0）、0043（祖父母の画面も同じ形）
- fable-advisor との相談（2026-11-05、デモの初期化での扱い）

## 見直す条件
- members に人ごとの状態の列がもう一つ増えたとき（人の状態を別の表に分け、初期化の対象にする形を考える）
- 撮影の筋が「返事をすでに見た状態」から始まるように変わったとき
- 返事が多い家族で、まとめて既読にすると見落としが出ると分かったとき

## クライアント（frontend-developer。言葉・見た目・流れは fable-advisor に相談 2026-11-05）

### 決めたこと
- タブは家族の画面も祖父母の画面も「返事」（0043: タブは両方同じ語。ひらがなは押す動作のボタンだけ）。並びは「今日」「アルバム」「返事」。開いたときは常に「今日」のまま
- タブの幅: 幅に余裕があれば等分、足りなければ語の長さに合わせて分ける（`repeat(3, minmax(max-content, 1fr))`。タブの中の横の余白は 0.25rem に詰める）。等分のままでは幅 360px・文字 150% で「アルバム」が一行に入らない。文字の大きさ（--font-aux）と高さ（--tab-height）は変えない。語の長さで分けると「アルバム」と「返事」の語が続いて読まれる（360px・150% で間が数 px）ので、タブの境目に細い線（--line、飾り）を置く
- バッジ: 「返事」の後ろに、まだ見ていない数の小さな丸。--accent の青地に白の数字（約 8:1）、数字は --font-sub（16px 以上）、99 を超えたら「99+」。見た目だけ（aria-hidden）で、読み上げは隠した文「、新しく n件」（「返事、新しく 2件」と読まれる。n は 99 を超えても実際の数）。aria-live は付けない（数が変わるたびに読み上げると割り込む知らせになる）。返事のタブにいる間は出さない。出たとき・数が変わったときだけ 0.25 秒小さく弾む（動きを減らす設定では動かさない）
- 0 件の一行: 家族「まだ返事はありません。あなたの語りや写真に家族が話すと、ここに届きます」（人間の例文）。祖父母「まだ返事は届いていません。あなたの話に家族が答えると、ここに出ます」（既存の空の文「まだ写真が届いていません。…ここに出ます」と同じ形。祖父母は写真を入れないので (b) は言わない）。アルバムは空で何も出さない（0034）が、このタブは何が来る場所か一行なしでは分からないため出す。読み込み中・読めなかったときは出さない
- 節（写真ごと）: 頭に小さめの写真（幅の 55%・16rem まで、高さは 12rem と画面の高さの 30% の小さい方まで。はみ出す分は切る。押すと拡大。0040）と写真の記録（撮影日・場所。0047。なければ出さない。入らなければ写真の下へ）。その下に Narrations（声は「聞く」と話者名の行の注、文字、「返事」。0045）。「n枚目」、写真の持ち主の名前、言葉の糸（0035）は出さない。0041 の見出しの小さい写真（48px）は押せないが、ここは帯がなく大きく見る道がこれだけなので押せる（大きさで見分けられる）
- 節の中に出すのは、届いた語りを含む糸（根の語りから下の返事まで）まるごと。自分の語りへの返事なら自分の語りが根として上に出る。このタブで自分が返した返事も糸の中に残る（送った返事が消えない）。届いたものを含まない糸（自分だけの語り、ほかの人どうしの糸）は出さない。何が届いたものかは src/shared/replies.ts の repliesFor に従い、まとめ方は src/client/lib/replies.ts
- 並び: 節は届いたものの最新の新しい順。タブを開いたときに決め、開いている間の読み直し（文字起こし待ち、前に戻ったとき、返事を送った後）では並べ替えない。開いている間に新しく増えた写真の節は上に足す
- まだ見ていなかったものの印は付けない（言葉も印も増やさない。節は新しい順、節の中は糸の順なので、届いたものは自分の語りのすぐ下に左の線つきで出る）
- 上に見出し・呼ばれ方は置かない（0043: 呼ばれ方は今日のタブだけ）
- 足さないもの: 「〇〇から返事が届きました」のような知らせの文、届いた時刻（「3分前」）、まとめ。出すのは家族の語りと写真の記録だけ（0034 と同じ）
- 返事の入力欄が開いている間はタブを描かない（0034）。入力欄は画面に一つ（今日のタブと同じ openReplyId を使い、タブを替えると閉じる）

### 見たことにする時
- タブを開いた瞬間に、手元の見た時刻を「そのとき手元にある届いたものの一番新しい createdAt」にしてバッジを消し、POST /api/replies/seen を一回送る（失敗しても黙る）。知らせが終わってから一覧を読み直し、届いた一覧でもう一度手元の見た時刻と並びを合わせる（この読み直しは「開いたとき」のうち。開いた瞬間に新しい写真が届いていれば、ここで一度だけ並びが変わる。サーバーの見た時刻は知らせの時点なので、知らせが届いていれば、読み直しで届いたものはサーバーでも見たことになっている）
- バッジの数は unseenReplies(repliesFor(feed, me), max(サーバーの repliesSeenAt, 手元の見た時刻))
- 開いている間に届いたもの（読み直しで増えたもの）は一覧に出すが、見たことにしない。タブを出るとバッジに出て、次に開くまで残る（画面に出ていても、下を読んでいて上に足されたものを見逃すことがある。書き込みは開くときの一回だけ）
- 退けた案: 閉じたときにもう一度 POST して、開いている間に出たものも見たにする（見ていないものを見たにしうる。書き込みが二回）

### 見直す条件（クライアント）
- 祖父母がタブ「返事」とボタン「へんじ」を別のものと受け取った → ボタンの語を見直す（タブは動かさない）
- 自分の写真への語り（返事でないもの）が「返事」に入ることに家族が戸惑った → タブの名前を人間に戻す
- 一つの写真に語りが多く、届いたものを探せないと言われた → 話者名の前に小さな印を足す
- 別の人のリンクの取り違えが起きた → このタブにも呼ばれ方を置く（0043 と同じ）
- タブの言葉を長くしたとき、タブを 4 つにしたとき → 幅 360px・文字 150% で一行に入るかを測り直す

### 結果（手元。架空の家族、playwright の電話の画面・タブレット）
