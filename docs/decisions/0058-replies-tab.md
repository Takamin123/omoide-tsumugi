# 0058 「返事」のタブ

- 日付: 2026-11-05
- 状態: 採用
- 決めた人: 人間（2026-11-05。タブに出すもの、祖父母の画面にも付ける、見たはタブを開いたとき・人ごとにサーバー）。デモの初期化での扱いは fable-advisor に相談（backend-developer）

## 決めたこと
- 「今日」「アルバム」の隣に 3 つ目のタブ「返事」を足す。家族の画面と祖父母の画面の両方。バッジにまだ見ていない数を出す
- タブに出すのは、その人について:
  - (a) その人の語りに、ほかの家族がした返事（narrations.reply_to_id がその人の語り）
  - (b) その人が入れた写真（photos.owner_member_id がその人）に、ほかの家族が残した語り（返事でないものも、返事も）
  - (a)(b) の重なりは一つに数える。自分の語りは数えない。声の語りは文字起こしの状態（pending・failed）に関わらず数える。返事の返事は (a) の一段だけを見る
- 「見た」はタブを開いたときにまとめて付ける。人ごとにサーバーに覚える（別の端末でも数が合う）

### サーバー側（backend-developer）
- members.replies_seen_at（integer、UTC のミリ秒、null 可）。null はまだ一度も開いていない（すべて未読）。既存の行は null
- GET /api/feed の応答に repliesSeenAt（この端末の人の値）を足す。型は src/shared/api.ts の FeedResult
- POST /api/replies/seen → 204（本文なし）。サーバーの今の時刻を入れる。クライアントの時刻は受け取らない（端末の時計のずれで数が狂わないように）。認証・家族の絞り込みはほかの入り口と同じで、触れるのはこの端末の人の行だけ
- 一覧と未読の数はサーバーで数えない。クライアントが feed と repliesSeenAt から、src/shared/replies.ts の repliesFor(feed, meId)・unseenReplies(items, seenAt) で作る。未読は createdAt > repliesSeenAt（ちょうど同じ時刻は見たことにする）。feed はもとから家族の語りをすべて持つので、増える読み込みはない
- デモの初期化（0038）は、その家族の members.replies_seen_at を NULL に戻す（同じ batch の中、WHERE family_id）。0038 に追記

## 理由
- requirements「入り口を開いた後は、家族同士が直接やり取りする」。自分の語りや自分の写真に家族が言葉を返したことに気づけないと、やり取りが一往復で止まる
- 数え方を一か所（src/shared/replies.ts）に置き、家族の画面と祖父母の画面で同じ決まりを使う。サーバーで数えないので、feed と数が食い違わない
- 0042 の g0（自分の語りへの返事がある写真を翌日の入り口の候補の先頭に置く）は、Claude の入り口で返事を運ぶ道。返事のタブは家族が自分で見に行く道で、g0 とは独立に動く（タブで見ても g0 は外れない。g0 は「その人の入り口に出したか」で決まる）

## 退けた案とその理由
- 見た時刻を端末に持つ: 別の端末（祖父母のタブレットと、手伝う人のスマホ）で数が合わない
- サーバーで未読の数を返す: 決まりが二か所になる。feed にすでに材料がある
- 語り一つずつに既読を付ける: 人間の決定は「タブを開いたときにまとめて」。表が増える
- デモの初期化で replies_seen_at に触れない: 前のデモでタブを開くと、初期化の後も印が 0 になり、「ボタン一つで同じ状態に戻せる」に反する
- 見た時刻を別の表に持って初期化の対象にする: 人間の指定は members の列。今は一列なので分ける利益がない
