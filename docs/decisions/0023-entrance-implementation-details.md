# 0023 入り口づくりの実装の小さな判断

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: fable-advisor に相談（backend-developer）

0017 を実装するときに、0017 に書いていなかった所を決めた。

## 決めたこと

- 添える家族の言葉は、**選んだ写真の語りからだけ**引用する（違反 `quote_other_photo`）。入り口の 4 つは一枚の写真にまとまる
- 候補が 0 枚（写真が少なく、前の 7 日に全部出していて、出した後の新しい語りもない）なら、Claude を呼ばずに固定の入り口（0009）にする。前の 7 日の除外は緩めない
- 毎朝の処理は一人ずつ順番に回す（並列にしない）。処理の始まりから 7 分（`MORNING_CLAUDE_BUDGET_MS`）を過ぎたら、残りの人は Claude を呼ばずに固定の入り口にする
- 問いかけの末尾の句点「。」一つは落としてから検査し、保存もその形にする。文の途中の「。」「？」「！」は二文として止める
- 問いかけの禁止語は NFKC で表記をそろえて照合する（「！」→「!」、「ＡＩ」→「AI」）。冒頭の相づちに「わぁ」「すてき」を足す
- 画像が読めない写真（保存先にない、5MB を超える）は候補から外す。キーがないときは画像も読まずに固定の入り口にする
- 失敗した人の理由は、`morning_done` の `fallbacks` に種類だけを出す（`not_configured`、`past_deadline`、`no_candidates`、`no_images`、`check_failed` と違反の種類、など）

## 理由

- requirements「入り口は 4 つでできている」「Claude の言葉は最小限」。別の写真の語りを添えると、家族の言葉がこの写真の説明に見え、結果として作り話の見え方になる
- 0017「同じ写真を続けない」はルールで守る。新しい語りがなければ Claude に足せる材料がなく、画像 6 枚ぶんの費用に見合わない
- 0009 と implementation-policy「毎朝届くことを優先」「10 分以内」。固定の入り口に倒れる形が先にあるので、予算切れは失敗ではない。順番に回すのは、費用とレートの上限を読める形にするため。一人の呼び出しは最長 2 分ほど（60 秒 × 2 回と待ち）
- 句点は家族に害がなく、方針（試す形・推測・相づち）とも関係ない。再試行は画像 6 枚ぶんの費用が倍になる
- 0017・0020「迷うものは止める側に倒す」。表記ゆれを機械でそろえ、最後の砦をプロンプトに頼らない

## 退けた案とその理由

- 別の写真の語りも引用してよい（話がそれた先がつながる例を活かせる）: 写真と言葉が食い違って見える。写真をまたぐつながりはアルバムの仕事
- 候補が 0 枚なら 7 日の除外を緩めて Claude を呼ぶ: 新しい材料がなく、費用に見合わない
- 人を並列に回す: 速いが、費用とレートの上限が読みにくい
- 句点つきを違反のまま再試行する: 費用の無駄

## 根拠にしたもの

- docs/requirements.md、docs/implementation-policy.md 2、0009、0017、0020

## 見直す条件

- アルバムに、写真をまたぐ語りのつながりを作るとき
- 本物の家族で、`fallbacks` の `no_candidates` が週の半分を超えたとき。7 日の除外を緩めるより先に、同じ写真に別の問いかけを作る価値があるかを考える
- ログの `fallbacks` に `past_deadline` が出たとき。先に候補の枚数（画像）を減らし、並列は最後
