# 0048 この写真に追加する（家族の手のむすび）

- 日付: 2026-11-04
- 状態: 採用（人間、2026-11-04: 親の試しの前に入れる）
- 決めた人: 作ること・試しの前に入れること・ボタンの名前「この写真に追加する」・上のメニューの名前「写真を家族に共有する」と登録後の一行は人間（2026-11-04）。データ・API・画面の形・言葉の細部は fable-advisor に相談（backend-developer。設計時の仮の名前は「この写真に足す」）

## 決めたこと

### 何をするか
- 家族の画面のアルバムの各写真の節（語りの欄）の末尾に「この写真に追加する」。押すとその場で写真を選び、選んだ写真（Z）を、表示中の写真（X）と一緒に家族の手のむすび（`musubi.created_by = 'family'`）に入れる
- 祖父母の画面・今日のタブ・拡大の画面（0040）には出さない。祖父母の画面の測定値（0043）は変えない
- 上のメニューの「写真を足す」は「写真を家族に共有する」に名前を替えて残す（人間、2026-11-04）。その画面で登録が終わったら「毎朝 1枚ずつ、家族の『今日』に届きます」の一行を出す。理由: 共有した写真はすぐには家族の画面に出ない（入り口として毎朝一枚ずつ届く。0017）ので、すぐ見えない戸惑いを防ぐ。「この写真に追加する」との違い（棚に入れて毎朝届くもの／今見ている写真に添えるもの）も名前で分かれる

### データ（マイグレーションなし）
- `musubi.created_by` は既に `'guessed' | 'family'` を持つ。`musubi_photos` の CHECK（confirmed なら decided_by・decided_at 必須）をそのまま満たす
- 家族の手のむすび: `created_by = 'family'`、`model`・`prompt_version`・`guessed_reason`・`guessed_evidence_record_ids` は null。写真の行は両方 `confirmed`、`decided_by_member_id` = 追加した人（cookie の人）、`decided_at` = 今
- X が既に家族のむすびにいれば（誰が作ったものでも、いちばん古いもの）そこへ Z を足す。推測のむすびにしかいなければ、推測のむすびには触らず新しい家族のむすび {X, Z} を作る
- 一枚が複数の家族のむすびに入ることは許す。統合しない
- Z が重複（同じ持ち主・同じ content_hash）でもつながりは作る。既に X と同じ家族のむすびにいれば何もしない（`linked = false`）。Z が X そのものならつながない（`link = null`）
- 家族のむすびは musubi_guess の「既存のむすび」に入るので、重なる推測は dropOverlapping で作られない（0044）

### API（src/shared/api.ts）
- `POST /api/photos` の meta に任意の `withPhotoId`。withPhotoId がこの家族の写真でなければ 404 not_found で、保存先（R2）にもデータベースにも入れない（保存する前に確かめる）。写真の insert とむすびの insert は一つの batch。応答 `{ photo, duplicate, link: { musubiId, linked } | null }`
- クライアントは一枚ずつ順に送る。一度に送れるのは `MAX_ADD_TO_PHOTO`（10 枚）まで（クライアントで確かめる）
- はずす: `DELETE /api/musubi/:musubiId/photos/:photoId` → 204。家族の手のむすびの、この端末の人が決めた行だけ消す。ほかの人の行・推測のむすび・ほかの家族・ないものは 404。rejected にはしない（行を消す）。写真は棚に残る。合言葉を確かめる入り口（確かめない入り口の一覧は増やさない）
  - 新しいむすびを作った人は X の行も自分で決めた行なので、API では X の行も消せる（消すと残りの写真同士のつながりが残る）。画面は追加した写真（Z）の「はずす」だけを出し、X の行を消す操作は出さない
- `/api/feed` の各 item に `addedPhotos`: 同じ家族のむすびにいる confirmed のほかの写真（Photo の形、place 含む）、古く追加した順。推測（guessed）は一切出さない（0044 のテストを「推測は出ない、家族の手の confirmed は写真としてだけ出る」に書き直した）
- むすびが読めないときも feed は開く（addedPhotos が空になるだけ。ログは種類だけ）
- 運営の記録の画面のむすびに `createdBy`（家族の手と推測を見分ける）

### アルバム（家族の画面だけ）
- 節の末尾に、追加した写真の列（48px 角、間 8px、押すと拡大、読み上げ「追加した写真」、0 枚なら出さない）→ ボタン「この写真に追加する」（白い枠、「返事」と同じ重さ）
- 選んでいる間はボタンの場所に「3枚のうち 1枚」と進み具合の棒。終わったら列に新しい写真が現れ、下に「追加した写真 2枚」（＋「すでにある写真 n枚」「読めなかった写真 n枚」「送れなかった写真 n枚」）と「はずす」。タブを離れたら「はずす」は出さない
- 10 枚を超えたら「一度に追加できるのは 10枚までです」の一行で、何も送らない
- 出さない言葉: 求める文、「つながりました」「むすび」「同じ出来事」、！、お礼
- 見出し＋語り一つの高さ（0041・0043・0045）は変えない。語りのない写真はアルバムの一枚にならない決まりは変えない

### 入り口
- 変えない（候補選び pickEntranceCandidates、prompts/entrance/v3.md、入り口の検査）。家族のむすびは sameEventLinks で confirmed になり、g1a の先頭側、`<same_event status="confirmed">` で渡る。g1a の条件は緩めない

### 間違ったつながりを運営が消す
家族が自分で「はずす」を押せない（タブを離れた、ほかの人が追加した）ときに、本人から頼まれたら運営が消す。家族 ID・むすびの ID・写真 ID は人間の手元（運営の記録の画面）から。値をリポジトリ・会話の記録に書かない。本番は人間が打つ。

```sh
# 見る（家族の手のむすびと、その写真）
npx wrangler d1 execute omoide-tsumugi --remote --command \
  "SELECT m.id, mp.photo_id, mp.status, mp.decided_at FROM musubi m JOIN musubi_photos mp ON mp.musubi_id = m.id WHERE m.family_id = '<家族 ID>' AND m.created_by = 'family' ORDER BY m.created_at, mp.created_at"
# 一枚を外す（写真そのものは消さない）
npx wrangler d1 execute omoide-tsumugi --remote --command \
  "DELETE FROM musubi_photos WHERE family_id = '<家族 ID>' AND musubi_id = '<むすびの ID>' AND photo_id = '<写真 ID>' AND musubi_id IN (SELECT id FROM musubi WHERE family_id = '<家族 ID>' AND created_by = 'family')"
```

## 理由
- 「同じ出来事」を家族自身が示す手段がなく、推測（0044）だけでは家族に見せられなかった。家族の手で決めたつながりなら、推測を出さない方針（0044）を崩さずにアルバムに出せる
- 既存の表と CHECK で足りるので、試しの途中でもマイグレーションなしで入れられる。入り口の選び方・プロンプト・検査を変えないので、出し比べをやり直さずに済む（confirmed のつながりは v3 が既に扱う）
- X の推測のむすびに Z を足さないのは、推測の行（出所のモデル・根拠の記録）と家族の手の行を一つのむすびに混ぜないため（requirements: 家族が語ったことと Claude の推測を混ぜない）
- 「はずす」を自分の行だけにしたのは、ほかの人が決めたことを黙って取り消さないため。rejected にしないのは、追加の取り消しは却下ではないため（rejected にすると、musubi_guess の dropOverlapping がその組を「家族が却下した組」として以後の推測から外してしまう）

## 退けた案とその理由
- X の推測のむすびを confirmed にする（家族が追加したら推測を確かめたことにする）: 家族が見ていない推測を確定にしてしまう
- むすびを一つに統合する（一枚は一つの家族のむすびだけ）: 二人が同時に追加したときの扱いが複雑になり、試しの前に入らない。今の量では重なっても困らない
- サーバーが一度に複数枚を受ける: 縮小はブラウザ（0003）で一枚ずつで、Workers のメモリにも優しい。一枚ずつ順に送れば途中の失敗も一枚ずつ数えられる

## 根拠にしたもの
