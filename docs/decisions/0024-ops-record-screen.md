# 0024 記録の画面は運営・開発用。運営の鍵で守り、本番では出さない。写真だけ返し、録音は返さない

- 日付: 2026-11-03
- 状態: 採用
- 決めた人: fable-advisor に相談（frontend-developer）。見るのは運営と開発だけ・合言葉とは別の鍵で守ることは人間（0017）。実際の家族の記録を運営が読むかは人間に預ける

## 決めたこと
- 入り口（focus、引用の出所と範囲、question、reason、model、prompt_version、input_narration_ids、トークン数、shown_at）、語り（transcript、cleaned_text、生の uncertain_spans、整形の model と版、文字起こしの状態、録音があるか）、photo_guesses を見る画面 `/ops/record` と、読み取りだけの `GET /api/ops/families/:familyId/record` を作る
- 鍵は新しい秘密を増やさず、家族を作る運営の Bearer（CREATE_FAMILY_TOKEN）。`Authorization: Bearer` で受け、時間が一定の比較で確かめる。設定がなければ誰も開けない
  - 合言葉の確認の一か所（routes/auth.ts の requireInvite）で、`/api/ops/` の下だけは合言葉の代わりに運営の鍵で確かめる。家族の合言葉の cookie では開かない。運営の鍵で家族向けの入り口も開かない。入り口の側（routes/ops.ts）でも重ねて確かめる
  - 画面は鍵をそのタブの sessionStorage にだけ持つ。localStorage にも URL にも置かない。写真は fetch に Authorization を付けて読み、blob の URL で出す
- 本番（APP_ENV=production）では、鍵が合っていても API は 404。画面はビルドに入れない。手元とプレビューのデモの家族で使う
  - 0014 の見直す条件「開発用の入り口が二つ目以上できたとき」に当たるので、/check と /ops/record を一つの規則の下に置く。サーバーは `devToolsOpen(config)`（routes/env.ts）、クライアントは `__CHECK_PAGE__`（開発用の画面を入れるか）を共に使う
- 写真は、Claude に渡したのと同じ縮小済みの画像を返す（`private, no-store`）。focus の比率はその画像に対するもの。録音は返さず「録音あり」だけを出す。緯度経度と保存先のキーは返さない
- 画面は家族向けではないので、言葉は words.ts に入れない（0014）。高齢の人の最低ラインまでは求めない
  - 最上部に「運営・開発用。家族には見せない画面」を常に出す
  - 「家族が語ったこと（出所つき）」と「Claude が決めたこと・推測」を見出しと枠（実線と点線、色も変える）で分ける。語りは transcript を「そのまま」として出し、整形（cleaned_text）は推測の枠に model と版を付けて置く
  - 入り口ごとに「家族に見えた形」（引用は「……」に置き換えた後の形と、問いかけ）を一か所に置く
  - 聞き間違いの印は、色に加えて［? ?］で囲み、波線の下線を付ける
  - 鍵が違うときと家族が見つからないときは、同じ言葉にする
  - 出さないもの: 緯度経度、タグや物体名の一覧、確信度・採点のような数値、評価の欄。語は「推測」「説明」にそろえ、「分析」「解析」「判定」「認識」を使わない
  - 家族の一覧を返す入り口は作らない（家族の ID を入れて開く）

## 理由
- requirements「写真と録音は非公開で保存する。合言葉を確かめた家族にだけ返す」の例外を実際の家族に作ることは、0014 が「人間に聞く」としている事柄。運営が読むことへの同意の仕組みがない今日は、本番に出さない
- 本番の CREATE_FAMILY_TOKEN の重さを「家族を作れるだけ」のままにする。新しい秘密を増やさない前提と両立する
- focus のずれは実物に重ねないと見えない。録音はこの画面の目的（入り口が平板でないか、理由が妥当か、focus がずれていないか）に要らない（渡すのは要るものだけ）
- 写真の説明をタグや数値で並べると画像解析ツールに見える（requirements「作らないもの」）

## 退けた案とその理由
- 本番でも使える（全家族）: 運営が実際の家族の語りを読む同意がない。鍵が漏れたときの被害が全家族の語りと写真に広がる
- 本番でデモの家族だけ使える: プレビューで同じことが見られる。is_demo の分岐が一つ増え、デモと実際の家族を分ける線に例外が入る
- 新しい秘密（運営の読み取り専用の鍵）を作る: 本番で出さないなら、今は要らない
- 録音も返す: 目的に要らず、鍵で返せるものだけ増える
- ID と比率だけを返す: focus のずれが見えない
- 鍵を localStorage に置く: タブを閉じても端末に残る

## 見直す条件
- 本番でデモを撮るとき、理由を見せたくなったら → is_demo の家族だけに広げる。実際の家族は 404 のまま
- 実際の家族の入り口の質を本番で見たくなったら → 人間に聞く:「本番で動く実際の家族の語り・写真・Claude の推測を、運営が記録の画面で読んでよいか。読むなら家族にどう説明し、同意をどこで取るか」。許されるなら CREATE_FAMILY_TOKEN の流用をやめ、読み取り専用の別の秘密に分ける
- 開発用の画面が三つ目になったとき → `__CHECK_PAGE__` の名前を、開発用の画面全体を指す名前に改める
