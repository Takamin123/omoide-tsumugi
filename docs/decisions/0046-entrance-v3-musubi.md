# 0046 入り口 v3: むすびを候補の並びと Claude の入力にだけ使う

- 日付: 2026-11-04
- 状態: 採用・既定は v3（人間の決定、2026-11-04: 親の試しの最中でも今すぐ切り替える。プレビューと本番に 0006 を当ててから入れる）。いなかった人への問いかけの形の偏りは、切り替えた後の様子で判断する。つながりの語の表は今のまま
- 決めた人: fable-advisor に相談（backend-developer。設計は取りまとめのエージェント経由）。今すぐ v3 に切り替えることは人間（2026-11-04）

## 決めたこと

前提: むすびの写真はどれも told の記録を持つ（0044 の検査）。むすびが足せるのは「受け取る人が語った写真 X と同じ出来事の写真 Y（ほかの家族の言葉つき）を次に出す」続きの向きと、「受け取る人がその場にいたか」の手がかりだけ。

### どこに使うか: 並びと Claude の入力の両方。問いかけの中身には使わない
- **候補の並びに g1a**（`pickEntranceCandidates`）: 生きているむすび（rejected とその家族の写真でないものを外して 2 枚以上残るもの。musubi-guess.ts の existing と同じ）で、Y と同じむすびの写真 X について、受け取る人自身が語った時刻（返事を含む）が、Y をこの人に最後に出した時刻より新しく、Y にほかの家族の語りがあるもの。並びは g0 → g1a → g1 → g2 → g3 → g4。g1a の中は confirmed を guessed より先、同じなら X への語りの新しい順。g0 に入る写真は g0 のまま。7 日の除外は g1a にも効かせる（g0・g1 のような免除はしない）。avoidPhotoIds（0042）は今までどおり。固定の入り口（pickFixedPhoto）は変えない
- **Claude への入力**（`prompts/entrance/v3.md`。v2.md は書き換えない）: 候補ごとに、同じむすびの写真を一行ずつ `<same_event with="P4" status="guessed" receiver_talked="2026-11-02"/>`。with が候補外でも ID だけ渡す。相手側の写真の語りの本文は渡さない
- **プロンプト**: これは機械の推測で、使ってよいのは写真の選び方と受け取る人がその場にいたかの判断だけ。問いかけで別の写真の出来事・つながり・順序を言わない。つながりを確かめる問いをしない。0024 の v3 の三つ（スキーマの `receiver_present: "yes"|"no"|"unknown"` を reason の前に、いなかった場合の例文、拾う語は画面に出る引用から）も入れた。0017 の範囲（推測を問いかけに出さない）は開かない

### 状態ごとの扱い
| 状態 | 並び | Claude への入力 | 問いかけ |
|---|---|---|---|
| rejected | つながりとして扱わない。生きている写真が 2 枚未満ならむすび全体を無視 | 渡さない | — |
| guessed | g1a、confirmed の後 | status="guessed" | 中身に使わない |
| confirmed | g1a の先頭側 | status="confirmed" | v3 では guessed と同じ制限 |

- 写真の組の状態は、**両方の写真が confirmed のときだけ confirmed**、それ以外は guessed とした（設計は「confirmed を先に」とだけ書いていた。片側だけが確かめられた組は推測を含むので guessed に倒した）
- 本番では実質 guessed だけ（家族の確定・却下の手段はまだない）。三つの状態の振る舞いはテストで固定（test/entrance-v3.test.ts）
- 入り口への答えで confirmed にしない（0044）

### 検査（entrance-claude.ts。全か無か、再試行 1 回は今までどおり）
- `question_asserts_link`: つながりの語（`ENTRANCE_LINK_WORDS`: 同じ日・同じ旅・同じとき・同じ時・同じ場所・同じところ・同じ出来事・同じ行事・同じ宿・続き・つづき・初日・二日目・三日目・翌日・次の日・前の日・前日。qa-engineer の指摘で算用数字の 2日目・3日目を足した）が問いかけにあり、選んだ写真の渡した語りのどれにもなければ止める。迷ったら止める側。照合は NFKC・空白なし・カタカナをひらがな・英字を大文字にそろえて行う（二つの検査とも）
- 語の表にない言い回し（おなじ日・あくる日・同じ頃・同じ年・最終日など）は止めない。「次の日曜」「初日の出」「手続き」「同じ時代」は部分一致で止まる（止める側の誤り。固定に倒れるだけ）。表を広げるかは本番の止まり方を見てから（見直す条件）
- `question_other_photo_words`: 渡した写真（候補と same_event の相手）のうち、選んだ写真以外の写真の told の記録の値（2 字以上）が問いかけにあり、選んだ写真の渡した語りにはなければ止める。記録は `repos.records.listByFamily`。設計の「渡した記録」は、Claude に渡した写真の記録と読んだ（Claude が目にしていない写真の記録は、偶然の一致しか起こさない）
- 入力の整合: same_event に出すのはその家族の写真・生きている写真だけ。別の家族のむすびが混ざらないことをテストで固定
- 「〜でしたか」の機械検査は作らない（出し比べで数える）

### 保存
- entrances に `input_musubi_ids`（JSON の配列）と `receiver_present` を ADD COLUMN（CHECK なし。マイグレーション `0006_entrance_v3`）。v2 と固定の入り口では null。運営と開発だけが見る（運営の記録の API の `guessed` に足した。画面では入り口ごとに、その場にいたか（いた・いなかった・分からない）と、渡したむすびの写真を「写真で見る」の一覧と同じ何枚目と小さな写真で出す。API はそのため、どれかの入り口に渡したむすびだけを写真と状態つきで返す（推測の理由・根拠は返さない））。家族向けの API に出ないことをテストで固定

### 切り替え
- `ENTRANCE_VERSION`（entrance-claude.ts の定数）で切り替える。既定は `"v2"`。v2 のときはむすびも記録も読まず、入力・検査・保存は今までと同じ
- 出し比べは `EVAL_PROMPT=v3` で v3 を名指しで呼ぶ。`EVAL_MUSUBI=0` で v3 のプロンプトのまま、むすびの入力と g1a を外す
- むすびと記録の読み出しが落ちたときは、`{ event: "entrance_same_event_read_failed", traceId, familyId, memberId, forDate, read: "musubi" | "records", errorType }` を残す（errorType は Error の名前だけ。メッセージは出さない）。morning_done の fallbacks の same_event_unavailable と処理の ID で突き合わせる
- **マイグレーション 0006 は、このコードを動かす前に当てる必要がある。** スキーマに列が入ったので、v2 のままでも entrances を読む問い合わせが新しい列を読む（drizzle は表の全部の列を指定する）。0006 のない D1 でこのコードを動かすと、入り口の読み書きが壊れる。だから、このブランチは親の試し（〜11/10）が終わるまで develop に入れない（試しの間に develop の直しを main にそのまま入れることがあるため）。入れるときは、`/d1-migrate` で本番とプレビューに 0006 を当ててからデプロイする
- 切り替え（`ENTRANCE_VERSION = "v3"`）は 11/10 の後、この記録の出し比べの結果と一緒に一つのコミットで

## 理由
- requirements「家族が語ったことと推測を分ける。推測は問いかけの形でしか使わない」「Claude 自身の言葉は最小限」。むすびは Claude の推測なので、家族に見える言葉（問いかけ）の中身には使わず、どの写真を出すか（並びと選び方）と、受け取る人がその場にいたかの判断にだけ使う。これなら推測が外れても、家族に見えるのは「別の写真が届いた」ことだけで、作り話にはならない
- 「翌日の入り口に活かす」（requirements）。前日に語った人に、同じ出来事のほかの家族の言葉が届けば、語りが家族の間を行き来する
- 0024 で v3 に送った課題（その場にいなかった人に自分の思い出を聞く）は、受け取る人がその場にいたかを先に決めさせると減る
- 方針はプロンプトに書くだけに頼らない（implementation-policy 2）。つながりの断定と別の写真の語は、機械の検査で止める

## 退けた案とその理由
- **推測を問いかけに出す**（「同じ旅の二日目ですね」「この夜の盆踊りの後は」）: 推測が外れたとき、家族に作り話が見える。確かめる形にすれば試す問いになる（0017・0020）
- **選び方だけに使う**（Claude に same_event を渡さない）: 並びだけでは Claude が 6 枚から選ぶとき（0017）に続きの向きが効かない。その場にいたかの手がかりも渡せない
- **相手側の写真の語りの本文も渡す**: 別の写真の言葉が問いかけに入りやすくなる。0023「入り口の 4 つは一枚の写真にまとまる」に反する
- **二枚目の写真や、つながりの印を家族に見せる**: 推測を家族に見せることになる。家族の確定の手段ができてからの話（見直す条件）
