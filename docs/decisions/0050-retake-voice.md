# 0050 送った直後の声の語りを取り直す（とりなおす）

- 日付: 2026-11-04
- 状態: 採用
- 決めた人: 案 A（行を消して取り直す）と、消せなかったときの文を祖父母も漢字まじりにしたのは人間（2026-11-04）。データ・API・画面の流れ・言葉の細部は fable-advisor に相談（backend-developer）

## 決めたこと

### 何をするか
- 声で送った直後に「とりなおす」（祖父母）／「取り直す」（家族）を出す。押すと送った声の語りを消し、同じ返事の欄（ReplyBox）ですぐ録り始める（「おわる」で送る）
- 声のときだけ。文字には出さない。今日の答えとアルバム（今日のタブを含む）の返事の両方、祖父母・家族の両画面
- 消せなかったら一文を出し、録り始めない（録り始めてから消すと、消せなかったときに二本目が送られる）

### データ（マイグレーションなし）
- 行を消す（隠さない）。transcript・cleaned_text も行と一緒に消える
- 消せるのは「自分の・声の・送って 10 分以内の・まだ何にも使われていない」語りだけ。条件はすべてサーバーが一つの条件付き DELETE で守る（`musubi.unlinkByFamily` と同じ書き方）
  - 使われている = 返事（`narrations.reply_to_id`）、入り口の引用（`entrances.quote_narration_id`）と入力（`entrances.input_narration_ids`、json_each）、記録（`records.narration_id`）、記録の取り出し（`record_extractions.narration_id`）、むすびの根拠（`musubi_photos.evidence_narration_id`）。どれかがあれば消さない（NOT EXISTS。外部キーの違反で 500 にしない）
- 録音のファイル（R2 の audio_key）は D1 の行を消した後に消す（0031 と同じ順）。R2 で失敗しても 204（ログは種類だけ）
- 文字起こし・整形の背景処理と毎朝の処理は変えない。行が消えた後に終わっても、条件付き UPDATE が 0 件になるだけで行は戻らない（テストで固定）

### API（src/shared/api.ts）
- `DELETE /api/narrations/:id` → 204。期限は `RETAKE_WINDOW_MS`（10 分）
- 条件: cookie の家族、cookie の人が話した人、kind = 'voice'、created_at ≥ 今 − RETAKE_WINDOW_MS、上の「使われている」がどれもない
- 外れたものは、理由を区別せずすべて 404 not_found。二度目も 404
- 合言葉を確かめる入り口（確かめない入り口の一覧は増やさない）
- ログ: `narration_retaken`（familyId、narrationId、speakerMemberId、kind、ageMs、hadAudio）。本文・録音のキー・URL は出さない
- クライアントは DELETE を自動で送り直さない

### 画面
- 「おくりました」「送りました」（.done）のすぐ下に補助のボタン（.aux。白い枠、48px 以上、祖父母は .elder .aux）。青にしない
- 出しておくのは、送ってから `RETAKE_SHOW_MS`（5 分。サーバーの期限より短くして、押した瞬間の期限切れを防ぐ）まで。次に答える・返事するボタンを押した、取り直しが始まった、画面を閉じたときにも消える（状態は手元だけ）
  - 祖父母: 「おくりました」は次の操作まで残す（0043 のまま）。ボタンだけ 5 分で消える
  - 家族: 声のときは「送りました」もボタンと一緒に残す（4 秒で消さない）。文字は 4 秒のまま
- 押したら: ボタンは押された形（aria-disabled）で待つ。204 → 知らせとボタンを消し、同じ ReplyBox で録り始める。失敗 → 一文を出し、[はなす][かく] に戻る
- 今日の入り口: 取り直しの録音が終わるまで段を動かさない（段が替わると ReplyBox が作り直されて録音が止まる）
- 0043 の高さの表を崩さない

### 言葉
- ボタン: 祖父母「とりなおす」、家族「取り直す」
- 消せなかったとき: 祖父母・家族とも「取り直せませんでした。前の声は残っています」（人間の決定: 祖父母も漢字まじり）
- 出さない: 「消しました」「もう一度話せます」「！」、お礼、「削除」「エラー」

## 理由
- 0008 で退けた「送る／やり直す」は、止めた後の動作を三つにして話す前に構えさせるためだった。送った後に補助のボタンを一つ出すだけなら、話す前の流れは変わらない。送りたくない声（言い間違い、途中で切れた）を直す道がないことのほうが、親の試しで「送りたくないものが送られた」として起きやすい（0008 の見直す条件）
- 行を消すのは、隠すだけにすると、文字起こし・入り口・記録など語りを読むすべての場所に「隠れているか」の条件が要るため。消せる時間を短くし、何にも使われていないものに限れば、消しても他の表が壊れない
- 条件を一つの条件付き DELETE に入れるのは、確かめてから消す間に返事や記録が付く隙をなくすため（対話的なトランザクションが使えない D1 でも成り立つ）
- 理由を区別しない 404 は、ほかの人・ほかの家族の語りがあるかどうかを漏らさないため（0048 の「はずす」と同じ）
- ボタンを 5 分、サーバーを 10 分にするのは、押した瞬間に期限が切れて「取り直せませんでした」になることを防ぐため
- 消せなかったときの文は、前の声が残っていることを言えば、もう一度押すか、そのままにするかを家族が選べる

## 退けた案とその理由
- 行を隠す（削除の印を付ける）: 語りを読むすべての場所に条件が要り、漏れると消したはずの声が出る。消したものを戻す必要もない
- 文字の語りにも出す: 文字は送る前に読み直せる。ボタンが増えるだけ
- 押したら先に録り始め、送るときに前を消す: 消せなかったときに二本目が送られる
- 期限なしで自分の声を消せる: 家族が返事を書いた後や入り口に使われた後に消えると、話の流れが壊れる。消すことそのものは 0027（家族の場を消す）の道がある
- 理由ごとに違う応答（403・409）: 画面で出す文は一つで足り、ほかの人の語りがあるかを漏らす

## 見直す条件
- 親の試しで、取り直しの後に前の声が残っていると言われた → 消す順と R2 の失敗のログを確かめる
- 5 分では足りない（送ってしばらくしてから言い直したくなる）と分かった → RETAKE_SHOW_MS と RETAKE_WINDOW_MS を一緒に延ばす（使われていない条件は変えない）
- 「とりなおす」を押して、録り始めたことに気づかない人がいた → 押した後の流れ（すぐ録る）を人間に戻す
- 語りを指す表や列を足したとき → deleteForRetake の NOT EXISTS に足す
- 毎朝の処理（記録の取り出し・入り口づくり）が語りを読んでから書くまでの間に取り直しが入り、外部キーの違反のログや、消えた語りを指す入り口が見つかったとき → 毎朝の処理の側で、書く時点で語りがあるかを確かめる
